# S4 原型设计与用户验证

UI/UX 资料有则复用，没有可暂不添加；由 AI 补足具体设计依据后，把确定的功能行为转为可操作原型。分开说明功能、品牌视觉、平台适配、用户验证的结论。输出 P04 可交互原型、T04《原型与验证说明书》及 Q04。

## 进入与接续

先按[本轮任务范围](../../references/task-scope.md)处理局部试用或小修改；此时只读取适用要求，保留成果、来源和实际检查，不强制补齐整阶段登记。以下完整成果与交接要求用于正式阶段推进；小任务不能据此宣称阶段生效。

先读 [公共契约](../../references/contract.md) 与 [本地命令](../../references/local-tools.md)，独立调用也先 discover/resume。读取当前有效 T03、系统页面布局、S3 功能验证原型及功能覆盖记录、相关 FUN/PAGE/RULE、T02、已有 VI/UI/UX 标准与适用 S3→S4 交接决定，采用确切版本。已有实际授权适用时复用，不重复询问。

任务或功能行为不清回 S3，企业规则空白回 S2，目标范围变化回 S1。必要业务输入缺失/失效时只推进独立草案，不能用原型替人决定；可选 UI/UX 资料未提供不属于此类阻塞。原始材料和历史成果不覆盖，不引入另一套项目状态。

## 执行

按 [v1.1 阶段基线](references/baseline.md) 执行 S4-A01—A08：

1. A01 用 [任务覆盖模板](assets/templates/task-coverage.md) 提取角色、任务、页面、关键状态与目标平台；按 [资料准入与成品评审协议](references/visual-readiness-and-finish-gate.md) 复用现有材料；提示用户有 UI/UX 资料可添加，没有则记录可后补，不等待上传。AI 从有效 S3 与目标平台形成具体暂定设计基线，常规选择无需另取批准，用 [资料准入模板](assets/templates/visual-material-readiness.md) 给 ready/not-ready；不能仅因未提供 UI/UX 判 not-ready。明确品牌强制要求、真实冲突或上游缺口才阻塞相依范围，其他工作可继续。
2. ready 后读取并执行本地适配的[原型构建方法](../../methods/prototype-build/SKILL.md)，按 A02 的[设计与实现映射规范](references/design-and-mapping.md)，从 S3 交接区分已定行为与可设计呈现，用[设计约定](assets/templates/design-contract.md)确定设备、布局、导航、视觉及组件用法和依据，在 T04 或同版附件维护“任务/规则→PAGE→区域→控件/状态”的唯一规格。常规设计由 AI 自主完成，局部修改只更新受影响部分。有选定图片/Figma 设计时，按方法核对实际可用专用 Skill、依赖及 HTML 导出/运行兼容后使用；没有参考不强制多方案，不自动发布。再按 A03 和 [HTML 原型规范](references/html-prototype-standard.md) 实现可操作 HTML，按[结构规格说明](references/page-structure-spec.md)核对来源、标识和必需覆盖。标明正式/AI 暂定样式及实际获准的偏离、示例数据与模拟响应，保存 [P04 说明](assets/templates/p04-prototype.md)。
3. A03 完成后准备 [冻结评审包](assets/templates/ui-finish-gate-packet.md)，让无开发上下文的 **UI Finish-Gate Reviewer** 实际对照适用品牌参考或 AI 暂定设计基线与实现截图，按 [独立评审模板](assets/templates/ui-finish-gate-review.md) 输出“结论 / 意见”。go 通过；no-go 修改后新建独立评审，不设固定轮次上限，真实阻塞则记待补；conditions-go 按本轮固定意见修改一次、执行者核对完成后通过，不重审。此关卡不代替功能走查与真人验证。
4. A04 对照同版规格，首轮从默认入口覆盖各核心路径、结果与返回；用代表性输入核对任务产物的质量、适用领域约束和可观察使用负担。按[共享平台与任务质量规范](../../references/prototype-presentation.md)及页面/视口计划实际操作信息、层级、状态、触控/滚动等适用检查，手机/小程序采用手机优先设计，浏览器模拟不冒充原生真机通过。按 [内部走查模板](assets/templates/internal-walkthrough.md) 定位 PAGE/区域/控件/状态，记录判据、实际产物、证据及模拟边界。先读工具/技能说明，不硬套 API；按需使用当前可用的 `product-design:audit` 辅助 UX/可访问性核查，结果回 Q04，不替代独立品牌关卡、任务操作或真人验证。结构检查、源码、截图或程序断言不能替代任务操作。
5. A05 内部检查通过后，用 [真实观察或豁免模板](assets/templates/user-observation-or-waiver.md) 准备任务和观察记录，由产品经理组织真实目标用户操作。没有真实观察或有权产品负责人的适用低风险豁免时，保持待验证；另一代理、专家评审、自动化和模拟反馈都不是目标用户。
6. A06—A07 用 [反馈与修订模板](assets/templates/feedback-and-revision.md) 判断源头阶段，先更新对应方案或设计约定及映射，再按稳定标识修改受影响区域、共享组件/样式和状态，避免无依据整页重生。保留旧版及标识去向，核对覆盖并重走相关任务与邻接路径，判断旧视觉结论是否仍适用，必要时由人补验。新范围/标准另立任务版本。
7. A08 使用 [T04 模板](assets/templates/t04-prototype-validation.md) 保留五章，分别说明四类结论、未执行范围、资料准入、独立评审和版本关系。

## 提交人工审核

按 [面向人工审核的写作规范](../../references/review-writing.md) 编写 P04/T04：先给可打开的原型入口、这次要看的任务、结论与尚未验证的风险，再给业务说明，版本编号和技术证据集中放附录。用一个具体任务说明“从哪里开始、做什么、应看到什么”，让产品经理和业务负责人能直接尝试；不要让人先读任务编号表才能操作。

审核摘要分别写清功能、品牌视觉、平台适配、用户验证的状态与证据，用中文解释 go/no-go/conditions-go 和下一步；临时样式通过不写成正式品牌符合，不用一个“通过”覆盖全部。需要人处理的事项写成具体决定：选项、建议理由、各自影响、适用任务与版本、谁能回复；没有新的决定事项就写明。沿用适用的真实决定，内部修正和已授权工作继续推进。

## 保存与门禁

TASK/P04/T04 用共享 put 保存，refs 引用实际使用的上游及任务/原型版本。P04 的正文是入口和版本说明，evidence 必须绑定实际自包含 HTML 快照；不能拿 Markdown 或静态图充当可交互原型。存放约定见 HTML 规范。

专业方法与外部 Skill 的采用范围、来源及实际执行情况按[接入规则](../../references/specialist-methods.md)记入 T04/Q04 或既有附件；执行本地适配方法不冒称执行了原版 Skill，不另建规格或阶段状态。

Q04-01—06 保留原编号，将来源/标识/必需区域与状态覆盖纳入 01/03，信息、权限、反馈及布局的实际核对纳入 02/03，增量复验纳入 05，设计/规格/实现及证据同版纳入 06；资料准入和适用独立成品评审证据继续保留。辅助脚本仅核验声明、文件/报告结构及处理分支，不替代实际审阅或操作。实际浏览器操作形成内部证据；validation=verified 必须来自真实用户任务观察，waived 必须有实际有权决定、低风险理由和范围。P04/T04 均须绑定适用证据；没有则不能 promote 或交接为有效成果。

向用户展示原型/说明的位置、版本、实际操作范围、已验证与未验证内容、问题及下一步；只有必要决定、真实验证或有效豁免、复核和版本满足门禁才生效。产品经理实际同意继续后 handoff S4→S5，同时包含 P04/T04。每轮 checkpoint 到具体 A 步骤，不能把“原型可点击”报告成“用户验证通过”。
