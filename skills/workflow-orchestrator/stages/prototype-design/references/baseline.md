## S4-A01 核验 VI/UI/UX 材料，确定任务与验证范围

从最终有效 T03、系统页面布局、S3 功能验证原型及功能覆盖记录、FUN/PAGE 和规则提取必须完整执行的任务、必要页面、关键状态及目标平台，用 [任务覆盖模板](../assets/templates/task-coverage.md) 记录验证目的和来源版本。任务不清回 S3，未知规则回 S2，不为展示效果扩功能。

首次走查前按[共享平台与任务质量规范](../../../references/prototype-presentation.md)选代表性输入，明确任务产物的内容正确性、后续用途、适用领域约束及可观察使用负担，并注明判据来源和模拟能力边界。没有独立产物文件的任务检查记录/状态与后续使用，不套用其他产品的领域字段。未知判据仅阻塞相依结论，不把准备计划写成已通过。

按 [视觉资料准入协议](visual-readiness-and-finish-gate.md) 判断最小视觉交付单元需要的品牌素材、字体/色值、UI 组件/版式、UX 导航/反馈、平台适配和可访问性资料。这里的单元是核对材料覆盖的任务或页面组及其关键状态，不在 A01 开发代表页。先复用已有文件、核验内容和版本、识别冲突；用户 UI/UX 资料可暂不提供，AI 从有效 S3 和平台要求形成具体暂定设计基线，仅真正需要人解决的阻塞合并补问。

用 [资料准入模板](../assets/templates/visual-material-readiness.md) 给 ready/not-ready 及证据。已有标准或具体 AI 暂定设计均可支持 ready，缺 UI/UX 上传不构成阻塞，常规设计不另取批准；S3 功能验证原型的适用界面、组件与已验证交互优先复用，演示样式须核对依据和正式要求，不能自动继承为品牌标准。not-ready 的相依范围不进入 A02/A03，非受阻任务可继续；不得虚构素材、品牌批准或以“先用默认”省略设计约定。

## S4-A02 确定生成前设计与页面结构

仅在 A01 ready 后，每页说明任务目的、必要信息、操作入口、状态、反馈和功能/规则引用，落实适用现有规范或 AI 暂定设计基线与 S3 页面布局。分别标注正式品牌样式、AI 暂定设计及有意偏离；偏离有理由、范围和实际批准状态，不能借此改变业务行为。新出现的关键资料缺口返回 A01，不能边开发边把未知标准定成事实。

读取并执行[原型构建方法](../../../methods/prototype-build/SKILL.md)，结合本轮范围裁剪。该方法供 S2/S3/S4 共用呈现和操作能力；S2/S3 演示样式可用不等于本阶段资料 ready。方法采用和实际专用 Skill 调用记录回 T04/Q04，沿用[专业方法接入规则](../../../references/specialist-methods.md)，不新增格式、审批或生效来源。

根据场景覆盖空、加载/处理中、成功、失败、取消、返回、权限不足等适用状态；这些是方案已有行为的表达，不能自行新定义权益、权限或结果。交互依赖未定功能或规则时回 S3/S2。

按[设计与实现映射规范](design-and-mapping.md)先核对 S3 已定任务、区域、信息含义/优先级、操作顺序、适用状态及来源，再在 T04 §2 或同版附件形成[设计约定](../assets/templates/design-contract.md)：设备与视口、布局与导航、视觉及组件用法、依据和适用范围。优先复用有效产品规范；AI 自主完成常规设计，重大产品取舍或真实冲突才请人决定。B/C 端、配色、字体、主按钮数量和装饰按任务判断，不设通用固定风格。

目标为手机 App/小程序时按手机优先设计；明确每个本期页面在主视口的检查安排，再按长内容、布局变化和状态风险选适用补测视口及复用范围。设计默认入口、各并列核心路径及结果返回，不能把单一页面或单一宽度当作整套产品适配。具体覆盖与浏览器模拟/原生真机的结论边界沿用共享规范。

建立任务/规则→PAGE@版本→区域→控件/状态→实现定位的对应，沿用 PAGE 内稳定标识并保持唯一维护源。必需信息/区域与状态从有效 S3 提取，不能仅从现有 HTML 反推覆盖。按[页面结构规格](page-structure-spec.md)维护 JSON、YAML 或清楚表格；自动检查的派生 JSON 标明主记录版本。完整新原型覆盖本期范围；小改动只补受影响部分及复用依据，不为局部任务重建全套设计记录。

## S4-A03 生成可交互原型与示例数据

按 [HTML 规范](html-prototype-standard.md) 实现自包含 HTML/CSS/JS，串联关键任务。模拟数据与外部响应在原型和 P04/T04 中可识别，不调用真实业务服务来制造“演示成功”。无需后端或 Figma 依赖。

有用户选定的图片/截图或 Figma 设计时，可按原型构建方法选择当前可用的专用 Skill；先读实际定义及依赖，确认当前任务获准的输入、输出与本地 HTML 交付兼容。框架产物须实际构建/导出并核对资源和运行，不能直接改名交付。不兼容时保留设计依据用本地 HTML 实现并说明；没有选定参考不强制三套方案，也不因插件流程自动发布。

交互控件有实际事件和可观察反馈，任务能从入口到业务结果。演示重置、角色切换、故障注入属于演示设置，不能混成产品功能；设定初始条件后仍要用正常产品入口完成任务。静态图片、无事件按钮、直接改变量跳到结果都不能证明关键任务可操作。

P04 记录可打开位置、版本、任务入口、示例数据、模拟响应及范围。无法产出可操作原型时可保存静态草案和缺口，但不把它声明为可用 P04 或进入真实任务验证。

实现保留规格约定的 PAGE/区域/控件/状态定位标记；生成后按[结构校验说明](page-structure-spec.md)检查来源引用、重复标识、必需区域与状态声明覆盖，修正差异后保留报告。静态标记存在不证明其实际可见或可操作，也不代替 A03 独立视觉评审与 A04 语义/任务核对。

### A03 完成后：UI 成品独立评审

冻结当前标准/资产、HTML、页面状态/目标视口截图、对照证据及有意偏离说明，采用 [评审包模板](../assets/templates/ui-finish-gate-packet.md)。以 fork_turns="none" 新建 **UI Finish-Gate Reviewer**，只给当前材料与评审要求，不给开发聊天、自评、期望判决或上轮结论。评审者实际查看参考与实现，按 [评审模板](../assets/templates/ui-finish-gate-review.md) 分“结论 / 意见”输出四类结论。

按 [分支协议](visual-readiness-and-finish-gate.md) 处理：go 通过；no-go 修改后新建独立评审，不设固定次数上限，真实缺口则记录待补；conditions-go 仅按本轮固定意见修改一次，执行者逐项核对已落实后通过，不再专家评审、不新增意见。没有真实审阅或证据不能声称通过。品牌、功能、平台、用户验证分别报告；成品评审不代替 A04、A05 或实际继续决定。关卡通过后进入 A04。

## S4-A04 实际操作关键任务并修正

先读取当前可用浏览器/计算机工具及相应技能说明，再实际打开原型。按任务点击、输入和触发交互，执行入口、主要操作、反馈、返回/退出、取消、重复和适用异常；核对页面、权限、状态、资源/权益反馈与有效 T03/T02。

首轮即从默认产品入口走完各本期核心路径并返回/接续，评审设置不能代替正常操作。用预先选定的代表性输入检查实际产物是否符合判据：内容正确完整、可供后续任务使用、符合适用领域约束，并记录可观察的额外整理或准备负担。实际产物与样例/规则对照留证，不以成功提示、可下载或漂亮 UI 代替质量判断；模拟算法、样图或材料不能证明真实能力及正式领域验收。

按同版设计约定与结构规格，实际查看必要信息是否出现且含义正确、信息层级和操作顺序是否服务任务、主次操作是否可识别、允许/禁止状态反馈是否符合规则，以及目标视口下的阅读顺序、导航、遮挡和输入保持。将差异定位到 PAGE/区域/控件/状态；记录来源预期与用户实际看到/操作到的结果，不仅报告按钮能点。

执行页面/视口/状态覆盖计划，检查适用长内容、空/错误反馈、触控与滚动、返回、放大阅读和保存入口的可发现性。记录实际浏览器及输入方式，区分窄屏、设备模拟与原生/真机结果；单一浏览器宽度通过不外推至全部手机。复用同版公共布局/组件证据时列出覆盖关系，原生容器或实物核验缺口保持明确。

记录工具环境、原型版本、前置数据、操作顺序、预期与实际结果、截图/可定位状态和问题。代码审查、单元测试、DOM 断言或截图可辅助检查，但不能替代实际浏览器操作。不要从页面脚本直接调用业务函数或改内部状态来冒充用户完成了任务。

UX 或可访问性问题可按需使用当前可用的 `product-design:audit` 辅助定位，先读取实际说明并遵守截图与证据要求；发现回现有问题台账/Q04。该审查不替代 A03 无开发上下文的品牌成品关卡、A04 实际任务操作或 A05 真人观察，三类结论分别保留。

断链、无反馈、状态显示错误由本阶段修正；功能/业务行为不明回来源阶段。修后再操作受影响路径。工具不能操作或无法读取必要证据时标明未检查范围，不能写已实测。使用 [内部走查模板](../assets/templates/internal-walkthrough.md)。

## S4-A05 由人组织真实验证，或记录适用豁免

内部检查通过后，AI 准备任务目的、自然任务说明、观察点与记录格式，产品经理组织真实目标用户操作。观察记录应有真实参与者角色、原型版本、实际动作、是否独立完成、受阻位置、必要帮助及原话/反馈，结论与证据相连。不要预填完成率、满意度或意见。

真实观察可来自人提供的合法记录，由 AI 整理并说明证据范围；不能让 AI 或代理扮演目标用户并登记为 verified。没有真实用户或记录时保留待验证，不因构建测试、自动化测试或内部专家走查通过而替代。

低风险验证豁免须实际有权产品负责人决定，明确适用对象/版本/任务范围、风险理由、限制和证据；AI 可提交具体评估供决定，不能自行认定低风险就批准。仅范围内适用，不把豁免写成已用户验证。采用 [真实观察或豁免模板](../assets/templates/user-observation-or-waiver.md)。

## S4-A06 分类反馈并回到来源阶段

根据原始反馈/内部问题的证据与任务影响分类：目标用户、问题、目标或范围变化回 S1；业务规则、职责、权益、权限或状态含义变化回 S2；能力、功能行为或任务路径设计变化回 S3；既定方案没有被原型正确表达的展示/交互问题留 S4。

同一反馈可能影响多个对象，先识别真正源头与依赖。不要把所有用户建议直接加成新功能，也不要只改页面绕过未定规则。重要取舍由人决定；上游先修订、核验并形成适用版本，随后同步原型。

问题台账记录原始证据、来源阶段、影响对象、阻塞性、处理建议、实际决定与责任人；缺信息时说明需要补查什么，不能把个人喜好当普遍用户结论。

## S4-A07 修订并复核，必要时补验

依据处理决定与更新的有效方案生成新原型版本，旧版及其验证证据保留。同步 P04/T04 和 refs，不改已登记快照。修改后重新执行受影响关键任务、状态和分支，记录实际结果。

生成前先更新对应方案或设计约定和页面映射，按稳定标识列出受影响区域、共享组件/样式、状态及应保持行为；仅在必要时扩大重构，并说明理由。保留同一对象标识，删除/合并/拆分记录旧标识去向。更新后重做引用和覆盖核对，再实际复验受影响任务、共享组件使用处及邻接返回/异常路径，避免局部修正带来无关整页变化或交互丢失。

判断改动是否影响原真实验证或豁免的适用性。若改变用户任务、关键反馈、规则或结果，明确需补验的范围，由人组织真实补验或取得适用决定；不能默认旧观察自动批准新版本。结论区分已解决、接受限制、延期处理和仍待决定；延期不能掩盖未关闭阻塞。

使用 [反馈修订模板](../assets/templates/feedback-and-revision.md)。判断资料准入和独立视觉结论对新版本是否仍适用，记录影响与依据。no-go 的再次评审使用新冻结包和新独立会话，不把上一轮判决/意见传给评审者；conditions-go 只核对原固定意见的落实，不借复核重启专家评审或追加第二轮条件。新范围/标准另立任务版本；实际功能缺陷仍须修正和复走。未受影响的原结论有依据才复用。

## S4-A08 核对原型、方案与验证版本

T04 按 [五章模板](../assets/templates/t04-prototype-validation.md) 包含任务覆盖、页面交互、验证记录、问题台账、验证结论与版本；P04 单独编号并绑定实际 HTML。核对 P04/T03/T04/TASK、RULE、A01 准入记录、独立评审与本轮意见处理的确切版本、可访问路径及证据；四类结论分别说明适用范围。脚本验证仅证明结构/文件及分支，不证明实际独立审阅。

Q-I 保留内部操作结论，Q-V 可采用实际操作/来源交叉核验或适用责任人复核，但都不能取代真实用户验证字段。shared record 的 validation=verified 仅用于真实任务观察；waived 仅用于实际有权低风险豁免。P04 与 T04 的记录分别绑定当前版本，可引用同一真实证据，必须覆盖各自引用的原型与范围。

未开展真实验证时，在 Q04-04 写“未执行/待验证”，不是“不适用”或“通过”。内部质量通过可以保留，但缺必要验证的成果不能标记有效。待验证确认或豁免决定时保持待人工决策；只有质量、必要结论/决定、版本和门禁满足才 promote。

## 建设测试边界

正向至少验证资料 ready 后从有效 T03 生成可操作原型、独立评审并用浏览器完成关键任务；正向另覆盖未提供 UI/UX 时自主形成具体基线继续、已有资料优先复用及后补资料增量校准；异常包括真实必要项 not-ready 时相依范围停在 A01、偏离强制品牌标准无适用决定时不放行、缺截图/工具时不伪造评审、三种判决各按对应分支处理。原有模拟外部失败/权限/重复操作及没有真人或有效豁免时仍待验证的检查保留。修订保留旧版并重走受影响任务；反馈上游变化返回来源。

建设夹具中的 TEST 观察或批准只能用于隔离验证控制机制，不是现实产品的用户验证结论。实际执行与结果由建设测试目录记录，本文件不声称案例已经运行或通过。
