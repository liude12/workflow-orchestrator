# 从产品方案到页面实现

本规范用于 S4-A02—A04 和 A06—A08。A01 按[当前资料协议](visual-readiness-and-finish-gate.md)处理可选 UI/UX 输入；独立视觉评审及真实用户验证保留，不新增阶段、成果类型或人工审批。

## 先读交接，再作设计

从有效 T03、页面布局、FUN/PAGE、任务覆盖和 RULE 版本提取：关键任务与结果、信息含义及优先级、操作顺序、适用状态、权限/规则来源，以及 S3 明确留给 S4 的展示选择。优先复用 S3 功能验证原型中适用的界面、组件与已验证交互；核对上游展示依据及正式要求差距，演示样式不能自动成为正式品牌标准。交接缺少关键功能含义回 S3，企业规则空白回 S2，不靠页面代码补定。

A01 ready 后、生成新页面前，用[设计约定](../assets/templates/design-contract.md)在 T04 §2 或其同版附件记录：

- 目标设备、输入方式、主要视口与适配边界，及其来源；手机 App/小程序按手机优先设计，桌面产品按实际任务设计；未实际测过的设备保持未测。
- 页面布局、导航、内容阅读顺序与窄屏重排方法，解释怎样服务任务；有依据的 S3 信息优先级和操作顺序必须保留。
- 复用的品牌/产品规范、字体、色彩、间距、组件和交互模式；标明确切版本、具体用法及正式或 AI 暂定范围、来源性质及实际获准偏离。
- 本期需新定的呈现方式与理由、涉及的页面/状态、与既有规范的差异及影响。

按[共享平台与任务质量规范](../../../references/prototype-presentation.md)，在同一设计记录中安排每个本期页面的目标主视口及适用补测视口、关键状态和复用依据。把默认入口、并列核心路径、结果与返回/接续一起设计，不把局部详情页当作完整产品。代表性输入、任务产物判据及模拟边界引用任务覆盖记录；质量标准涉及功能或业务变化时先回 S3/S2，不能以视觉选择替代。

已有产品优先复用有效规范。未提供 UI/UX 资料时，由 AI 按有效 S3 与平台形成具体暂定设计，不要求用户上传或批准每项常规选择；以后添加资料时核对差异、更新同一约定、局部修改并复验。AI 自主完成授权范围内的常规布局和视觉选择，不逐项请用户选颜色、字体或组件；只有冲突、缺失事实或影响业务/重要产品取舍时提出具体问题。B 端、C 端布局按任务密度、角色、使用场景和平台条件选择，不固定侧栏、卡片、主按钮数量或装饰比例；配色与字体也不以通用偏好替代已有产品标准。

## 页面结构保持可追踪

在同一份 T04 页面结构规格中建立“任务/规则 → PAGE@版本 → 区域 → 控件/状态 → 实现定位”。S3 交接的必需信息和结果是核对起点，不能只从已有 HTML 反推规格而漏掉尚未实现的需求。

沿用 PAGE；区域、控件和状态使用 PAGE 作用域内稳定标识，不登记新的成果类别。已有 S3 区域标识直接沿用；没有时在 S4 建立并链接具体来源。标识不依赖数组序号、屏幕位置或当前文案，同一对象改布局/文案不换号。列表重复项使用稳定模板控件加业务记录键定位，不为每条示例数据复制规格编号。删除、合并或拆分写清旧标识去向和理由，不能以改号掩盖遗漏。

每个必要区域说明任务目的、信息含义/层级、操作与反馈、可见/可用条件及来源；每个适用状态有触发前提、可见信息、允许操作、预期结果及实现位置。无直接企业规则的纯展示选择引用设计约定，不能伪造 RULE。明确不适用项及依据；“暂未实现”是缺口，不是不适用。

JSON、YAML 或清楚的表格均可作为唯一维护源；采用 JSON 自动核对时使用[页面结构规格与校验](page-structure-spec.md)。从表格/YAML 导出的 JSON 是带来源版本的派生检查输入，不能成为第二份独立维护的权威。完整新原型覆盖本期全部页面和关键任务；小修改只更新受影响部分，明确复用基线和局部范围，不补造无关记录，也不据局部结果宣称整阶段通过。

## 检查结构，也检查表达是否正确

生成 HTML 时按规格保留可定位标记，不能把标记显示为产品文案。自动检查引用、重复标识、必需区域和状态覆盖后，将结果纳入 Q04-01/03/06；工具只能验证声明、文件和标记的内部一致性。隐藏元素、标记或源码中有状态名，不证明用户能看见、理解或触发该状态。

在独立视觉关卡适用且通过后，A04 从有效任务/规则出发实际查看并操作，逐项核对：

| 核对对象 | 要观察的结果 |
| --- | --- |
| 信息与层级 | 必要信息实际出现、含义正确；关键判断和主次操作容易找到，不被次要信息遮蔽 |
| 操作与状态 | 操作顺序、前提、结果、反馈和返回/取消与 S3 一致；失败后的数据与重试正确 |
| 全局路径与任务产物 | 首轮从默认入口覆盖各核心路径、结果和返回/接续；代表性输入的实际产物符合约定的内容、后续用途与适用领域约束，记录可观察的整理/准备负担及模拟能力限制 |
| 权限 | 允许与拒绝角色/状态均按来源表达；不能仅隐藏按钮却留下可执行入口 |
| 布局与平台 | 按页面/视口/状态计划核对长内容、空/错误、触控、导航、滚动、遮挡及返回；适用的放大阅读和保存入口可发现；缩放/重排不丢输入或交互；浏览器模拟与原生/真机分别结论 |

记录规格位置、PAGE/区域/控件/状态、样例与选择理由、判据及来源、实际动作与产物、截图/可定位证据、版本和未测范围。产物质量检查与独立品牌/UI 评审分别记录，界面美观不证明任务产出可用。发现遗漏先修实现；功能/规则本身不明则返回来源。结构通过、内部任务通过、品牌/平台结论与真实用户验证分别报告；不从“能点击”推导“方案正确”或“用户认可”。

## 按影响修改，不整页重生

先判断变化属于 S1 目标范围、S2 业务规则、S3 功能/路径，还是 S4 呈现。上游变化先更新对应有效来源及必要决定；S4 自主设计调整先更新设计约定和受影响映射，再修改 HTML。缺口相关部分保持草稿，独立部分可继续。

仅实现遗漏或错误时，保留原有正确规格，记录差异并修实现；不能为了让检查通过而删除必需区域、状态或改写预期。设计确有变化时才更新相应设计条款，检查输入从同一主记录更新。

依据稳定标识列出受影响区域、共享组件/样式、状态及关联任务，说明计划修改与应保持的行为。优先局部补丁并复用现有事件和状态管理；只有结构确有必要整体调整时才重构，记录影响和理由，不因一句局部反馈重写整页。

保留旧方案、规格、HTML 和证据，形成同版新快照。检查变更前后标识/来源及必要覆盖，再实际重走受影响任务、共享组件使用处和邻接返回/异常路径；未受影响部分复用需有依据。同步 P04/T04 与 Q04，依原规范判断旧视觉、真实观察或豁免结论的适用性，不复制旧通过结论。

## 保存与建设验证

设计约定和结构规格放在 T04 §2 或其同版附件，T04 正文引用唯一位置；随 T04 保存/快照绑定输入和 P04/HTML 版本。P04 不反向引用 T04 条目，避免循环。局部工作稿可先独立保存，正式登记/交接仍按既有版本和证据机制。

维护工具或模板时，用已填的 TEST 示例同时核对模板、规格、来源和 HTML；验证引用错误、重复标识、缺必需区域、漏状态会被报告。再以现有案例实际操作完整任务及一次局部修订，记录改动前后发现、修复与复验；没有对照证据时，不声称已经减少返工或代表真实用户效果。
