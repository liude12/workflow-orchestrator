| 用户操作 | 【具体动作/触发】 |

## 可判定验收

| 字段 | 填写内容 |
| --- | --- |
| AC ID / 版本 | 【填写】 |
| 关联 REQ / RULE / 原型版本 | 【填写】 |
| 验收类别与目的 | 【正常/异常/边界；要判断什么】 |
| Given 前置条件与初始数据 | 【可复现的角色、状态、必要条件】 |
| When 操作/触发 | 【具体动作】 |
| Then 可观察结果 | 【信息、状态、权限或业务结果；必要禁止副作用】 |
| 通过与失败判定 | 【观察什么即通过，什么情况失败；避免“处理正确”】 |
| 观察位置/业务凭据 | 【页面/记录/业务结果，来源依据；不编造技术接口】 |
| 未确定预期与阻塞范围 | 【填写；无则写无】 |
| 测试评审意见与来源 | 【实际意见；未评审明确填写】 |

需要多条 AC 时复制验收记录，覆盖关键正常/异常/边界。需要真实运行来证明的事项在另一个实际执行记录中记结果；AI 编写 AC 不代表执行验收通过。
