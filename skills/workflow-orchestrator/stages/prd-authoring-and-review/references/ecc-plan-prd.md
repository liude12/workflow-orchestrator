# 用 /ecc:plan-prd 生成 PRD 与承接 SRS

依据用户 2026-11-10 的明确要求，S5 新建 PRD、SRS 或实质重生成时，必须使用 `/ecc:plan-prd` 作为需求生成入口。先读取当前环境中实际安装的命令定义，核对版本和宿主支持的调用入口。本规范不安装 ECC，也不假定当前会话已经具备该命令。

## 命令职责与适用范围

已核对的 [ECC 官方命令定义](https://github.com/affaan-m/ECC/blob/b38be6a7f6350964d59328b52f0624e1d1d552d1/commands/plan-prd.md)属于 ECC 2.2.3：它围绕问题、证据、用户、假设、指标、范围、里程碑、待决与风险生成 PRD，默认输出 `.claude/prds/{name}.prd.md`，未定义自动生成 SRS。实际安装版本不同，先核对其定义，再记录差异，不猜参数或能力。

因此双文档流程为：有效 S1—S4 输入 → 实际调用 `/ecc:plan-prd` → 核对其 PRD 结果 → 按本阶段模板整理十一章 PRD → 依据该 PRD 及有效上游展开六章 SRS → 完成追踪、Q05、真实评审和同版 T05 登记。SRS 的详细行为仍必须有业务与产品依据，不能仅从精简 PRD 推测。不得声称官方命令直接产出了它未生成的 SRS。

本地[能力约束与规格方法](../../../methods/capability-specification/SKILL.md)只在复杂跨系统、迁移、权限/权益、状态关联或必要首次详细规格展开时辅助核对有效 PRD 与现状契约。它不替代真实命令调用，也不改变十一章 PRD、六章 SRS 及同一 T05 结构。方法和外部 Skill 的实际采用分别按[接入规则](../../../references/specialist-methods.md)记录；命令未执行时可借助方法核查已有规格、整理输入和冲突，不能使用它绕过生成要求。

单独生成 SRS 时，先核对它采用的 PRD 是否有覆盖当前范围和基线的实际命令记录；有则复用，无则先通过该命令生成或更新 PRD。旧项目无需仅为迁移重新生成历史文档；下一次新建或实质改写时适用此要求。纯错字、排版或链接修复不强制重跑，保留原生成来源并核对一致性。

## 执行输入与结果处理

1. 整理项目位置、本轮范围、有效 T01/T02/T03/P04/T04 的版本和可读入口、已确认决定、必要验证结论，以及已有 PRD/SRS 和稳定编号。已有信息直接带入命令上下文；只对缺失或冲突的必要内容补问，不把已答问题重新交给用户，也不代用户虚构回答或跳过决定。
2. 在支持 ECC 的宿主通过真实命令入口调用 `/ecc:plan-prd`，请求依据这些材料生成当前范围的需求稿，保留未知项与来源。参数和交互以实际定义为准。斜杠命令不是 PowerShell/Python 命令；只写一行命令、阅读定义、转述方法或让未配置 ECC 的代理自行写稿，都不算已调用。
3. 保留返回结果及原始输出位置，核对命令是否真正执行成功、输出是否对应本轮输入。只有启动记录、失败回复或部分输出时如实记状态。默认目录中的稿件是生成中间成果；后续正式正文按项目原有布局保存，不另建一套生效记录。
4. 对照上游审查输出，复用项目已有编号。命令提出的新范围、业务规则、状态或权限先回相应来源阶段处理，未知指标和假设保持待定。随后整理 PRD 和 SRS，逐项对应功能、通用约束、DEC、REQ/AC 与适用原型位置，依照[双文档写法](prd-srs-writing.md)核对两份正文。
5. 记录实际调用方式、定义来源/版本、输入基线、执行结果、原始产物及最终 PRD/SRS 的对应位置。放入现有 R05/Q05 或 T05 追溯附件，正文链接即可。既有命令产物可复用的前提是当前范围、输入及结论仍适用；实质变化先修上游，再用命令处理受影响内容并同步双文档，保留旧版和复检证据。

命令提示的 `/plan` 属于研发实施规划；本次 S5 工作不据此自动启动架构、编码或提交。现有需求评审、阶段交接及交付授权规则继续适用，命令执行成功不代替这些结论。

## 不可用与失败

先在当前可用工具、已安装插件/命令目录及用户指定位置查找。缺少安装或宿主不支持调用时报告“`/ecc:plan-prd` 未执行”；已调用后返回错误则记“执行失败”，只有部分产物则记“部分完成”。在 R05 保留实际查找范围或调用返回、错误、受阻工作和恢复条件。可继续整理输入、核对已有文档及准备调用材料；依赖该命令的新生成或实质重生成保持未完成，不静默改用普通写作、`prd-development`、`/plan` 或手工套模板。

不因缺失而自动安装全套 ECC 或改全局配置。当前任务若只是更新本 Skill，可以完成规则、模板和静态检查，但必须区分“接入规则已完成”与“真实命令联调未完成”。单纯未安装不撤销历史有效成果，新增生成要求也不追溯伪造历史调用记录。

## Q05 的核查位置

- Q05-01：适用输入和命令入口可用性；缺失/失败时说明受阻部分。
- Q05-02：命令输入、PRD 输出、最终双文档与 REQ/AC 的实际对应及覆盖。
- Q05-03：生成结果的行为、条件、状态与权限可理解，SRS 有足够上游依据。
- Q05-06：当前双文档基线与执行记录相符，正式登记仍使用同一 T05 和 SRS 阅读附件。

`workspace.py` 的 gate 只检查已有登记约束，不自动调用 ECC，也不认证调用记录真实性。未执行不能记通过；真实命令联调、文档内容核对和登记工具测试分别报告。
