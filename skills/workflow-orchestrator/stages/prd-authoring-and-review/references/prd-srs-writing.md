# PRD 与 SRS 的结构和写法

S5 默认交付配套的《产品需求文档 PRD》和《软件需求规格 SRS》。PRD 面向产品经理与业务负责人，呈现用户价值、业务范围、功能及验收承诺。SRS 面向研发和测试，展开这些承诺对应的条件、输入输出、状态、权限、关联影响和可验证结果。两份文档采用同一产品目标、范围和已确认业务依据。

这一约定来自用户在 2026-11-05 提供的两份 v0.2 参考文档。参考的产品名称为“健身会员服务与教练运营平台”。复用其目录组织、业务表达和细节粒度，按当前项目替换业务领域。来源指纹列在文末。

按用户 2026-11-10 的新增要求，生成流程必须经过 `/ecc:plan-prd`，具体调用、SRS 承接、复用与不可用处理见[命令接入规范](ecc-plan-prd.md)。以下目录与写法用于整理命令结果及配套规格，模板本身不代替实际调用。

## 两份文档的阅读方式

PRD 顶部保留产品名、版本、日期和实际状态，再用一小段审核摘要说明当前结论、变化、最重要的缺口和需谁决定什么。随后使用十一章结构，依次为文档定位、背景与问题、产品目标与成功标准、用户与权限、范围与主流程、功能需求、通用质量与业务约束、交付里程碑、待决事项、风险、来源索引。按业务领域分组功能，每条写需求和可观察的验收结果。[PRD 模板](../assets/templates/t05-prd.md)

SRS 采用六章结构，依次为能力概述、约束与不变量、实现契约、范围边界、待决事项、交接结论。第三章保留角色入口、权限、需求明细、状态转换、逻辑接口与外部依赖、数据含义、适用政策、质量与运营、集成验收。对实际存在的跨对象同步、并发、重复提交、结果未知和恢复路径展开说明。AI、语音、支付等能力仅在本项目已纳入范围时写入。[SRS 模板](../assets/templates/srs.md)

正式正文写完整业务句子。一段说明一个问题，表格承担可比较信息。PRD 的功能表通常用“编号、需求、验收条件”三列，SRS 的需求表用“编号、需求与输入、处理结果和可验证条件、PRD 来源”四列。按语义拆表或补充步骤，避免一格堆入整套流程。技术维护编号、哈希、逐项检查和原始反馈放到追溯记录，通过明确入口查阅。

## 规格如何承接产品承诺

- PRD 给每项能力和通用约束明确的验收结果。SRS 的每条需求都能回到对应 PRD 功能或通用约束，跨条目流程还要列出完整的集成验收路径。
- 同一业务对象在何时创建、由谁处理、可以转换成什么状态、影响哪些其他对象，以及部分成功或失败后如何继续，按真实依据展开。项目尚无依据时，写具体待决问题、阻塞范围和确认职责。
- 输入输出描述业务含义、校验和返回结果。技术方案已确认时引用其版本，尚未确定的数据库结构、协议、供应商和技术栈列入相应设计工作。
- 写清当前 PRD 的有效状态。已确认基线、规格建议、待核实事实和待决事项在相关条款处标注，建议新增的规则先提交对应责任人。PRD 处于草稿时，SRS 按同一草稿范围展开并标明可推进边界。
- 成功指标写测量定义、基线、目标和验证方法。未知数值写待确定及确认方法。里程碑按用户可完成的业务结果分组，状态采用实际进度。
- 交接结论分别说明文档是否可评审、哪些范围可进入后续工作、哪些产品澄清或架构设计尚待完成，以及实际已检查的范围。

## 编号与两份文档的对应

沿用项目已有稳定编号。新项目可按参考采用 PRD 的 `FR-领域-序号`、`QR-序号`，SRS 的 `REQ-序号`、`CON-序号`、`INT-序号` 和 `QLT-序号`。两份文档共用同一组待决编号 `DEC-序号`，在待决记录中维护决定和依据，通过引用呈现相关影响。新增与修订保留历史编号关系。

这些是供读者查阅的文档编号。用追踪表把它们映射到共享工作区真实的 REQ、AC、SRC、RULE 等成果及确切版本。一个功能可以对应多条规格与验收。核对 PRD 到 SRS 的正向覆盖和 SRS 回 PRD 的反向来源，通用质量要求和已确认决定也要对应。保存依赖按上游 → REQ → AC → T05 排序。[追踪模板](../assets/templates/requirements-traceability.md)

## 对既有 S5 实质要求的承接

原建设方案的十章覆盖内容分配到以下位置。旧项目修订时按内容迁移，保留实际业务决定与来源。

| 原覆盖内容 | 当前阅读位置 |
|---|---|
| 产品概述 | PRD 第 1—5 章 |
| 业务概述 | PRD 第 2、4、5 章，SRS 第 2、3 章 |
| 功能结构与索引 | PRD 第 6 章及需求追踪表 |
| 功能详细规格 | SRS 第 3.3 节及适用补充流程 |
| 页面与交互 | PRD 第 5 章的系统布局和原型入口，SRS 第 3.1、3.3 节 |
| 数据与权限 | PRD 第 4 章，SRS 第 3.2、3.6 节 |
| 异常与边界 | SRS 第 3.3—3.5、3.9 节及第 4 章 |
| 验收条件 | PRD 第 6、7 章，SRS 第 3.9 节和 AC 主记录 |
| 评审及变更记录 | 两份文档的审核摘要、待决章节及评审处理记录 |
| 交付与版本 | 两份文档的版本头、SRS 第 6 章及交付清单 |

Q05-01—06 沿用既有检查编号，按两份文档合并覆盖执行。复核和具体清单批准覆盖本次双文档版本。
