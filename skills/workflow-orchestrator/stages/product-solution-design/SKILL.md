# S3 产品方案设计

说明产品怎样支撑本期业务，并用可交互功能验证原型（原称粗原型）核验功能承接是否完整。输出 T03《产品功能方案说明书》、全系统初步页面布局、可操作 HTML 功能验证原型与实际覆盖记录，以及适用 FUN/PAGE/NFR 和 R03/D03/Q03；布局与功能验证原型是 T03 的同版附件。

## 进入与接续

先按[本轮任务范围](../../references/task-scope.md)处理局部试用或小修改；此时只读取适用要求，保留成果、来源和实际检查，不强制补齐整阶段登记。以下完整成果与交接要求用于正式阶段推进；小任务不能据此宣称阶段生效。

先读 [公共契约](../../references/contract.md) 和 [本地命令](../../references/local-tools.md)，独立调用也先 discover/resume。读取 T01、T02、配套业务验证原型及实际记录、实际使用的 SCN/RULE 的确切有效版本、来源、产品约束及适用 S2→S3 交接决定；已有实际授权适用时复用。原件先 snapshot，不建立另一套状态。S2 模拟控件帮助理解业务，不作为已确定的产品页面或功能结构；S3 从业务结果映射能力并形成布局/功能验证原型，复用适用规则、测试数据、界面样式与组件，按 FUN/PAGE 和任务重新核验产品组织及功能覆盖。接续旧项目缺少 S2 原型时记录缺口、判断受影响范围，补齐所需验证，不将缺失误记为已有通过。

输入缺失或失效时，只推进不依赖缺口的草案，记录阻塞与下一步，不伪造上游有效。目标范围问题回 S1；业务场景、规则、权限或状态含义不清回 S2。已有产品优先复用有效功能和已确认约束；先实际打开现有原型、观察任务入口和状态，再判断新增、复用或替换，不能只读页面清单便另做一套。

## 执行

读 [v1.1 阶段基线](references/baseline.md)，按 S3-A01—A08 的依赖与缺口执行：

新系统、多入口任务组织、大功能拆分或行为不清时，按[专业方法接入约定](../../references/specialist-methods.md)读取并执行[任务组织与功能方案方法](../../methods/task-solution/SKILL.md)的适用部分，再回填下列既有模板。已有路径和行为足够的小修改只更新影响项，不额外制作完整故事地图。

1. 用 [场景能力映射模板](assets/templates/scenario-capability-map.md) 分清产品、人工和外部系统各自处理的业务步骤，标明交接与边界。业务动作不机械等于功能或页面。
2. 按任务、对象和角色组织模块与共享能力，说明新增、复用、依赖及本期边界；每个新增能力要有目标或业务依据。
3. 用 [功能行为模板](assets/templates/functional-behavior.md) 明确角色、入口、前提、输入与校验、操作、系统响应/反馈、结果、权限、状态和重要异常，引用有效 RULE，不在功能描述中补定企业规则。
4. 用 [页面布局模板](assets/templates/page-layout.md) 给出全系统页面清单、页面数量口径、各角色导航、每页功能与内容区、主次操作和布局草图，说明平台假设。将关键任务对应到 PAGE、必要区域、信息含义及层级、操作顺序、适用状态和规则来源；区分已确定的行为与留给 S4 自主选择的展示事项，区域标识在 PAGE 内保持稳定。区分独立页面、弹窗/抽屉和页面状态；串联入口—操作—反馈—结果—退出/返回，检查适用空状态、失败、取消、重复和权限反馈。可放在 T03 §4 的独立部分，内容较多时用独立附件并在正文保留总览。
5. 仅当结构、体验、依赖或风险存在需选择的实质差异时，使用 [方案比较模板](assets/templates/solution-comparison.md)。重要取舍交实际产品经理决定；没有实质差异写明依据，不强造多套方案。决定后同步功能、权限、状态与路径。
6. 用 [T03 模板](assets/templates/t03-product-solution.md) 先整理可审核的功能与布局方案，落实适用的实际决定；读取并执行[原型生成适配方法](../../methods/prototype-build/SKILL.md)的 S3 适用部分，再按 [功能验证原型规范](references/rough-prototype-standard.md) 生成自包含 HTML，增量修改复用已验证界面和交互。按[共享展示规范](../../references/prototype-presentation.md)落实目标平台、各角色产品入口、本期页面和连续任务，默认进入用户界面，评审工具独立打开；用真实事件完成输入、校验、状态改变、权限反馈及返回。展示质量接近 S4，无正式品牌时 AI 自主形成有标记的演示样式；不能仅交几个功能控件或为凑成 App 增加无依据业务。
7. 对复杂角色、状态或多对象联动，用[场景覆盖方法](../../methods/scenario-coverage/SKILL.md)核对用例与断言；已有完整覆盖可复用。用 [功能验证原型与覆盖记录模板](assets/templates/rough-prototype-and-coverage.md) 在真实浏览器逐项操作，从 T02 场景/规则/异常追到 FUN/PAGE、页面操作与可观察结果，再反查功能的来源和范围。未执行写未测试，不得判通过；源码、截图和文字推演不能代替操作。缺陷回填功能方案、布局和功能验证原型并复检后，按 [R03/D03/Q03 模板](assets/templates/r03-d03-q03.md) 汇总；最终 T03 与附件必须一致。

## 给产品经理和业务负责人审核

编写前读取 [面向人工审核的写作规范](../../references/review-writing.md)。T03 先说谁从哪里操作、产品怎样回应、最终解决什么问题，再说明采用方案的理由、关键变化、本期边界和需人决定的事项。正文用一个完整任务贯穿功能、页面、权限和异常，不能只列功能名称或把关键行为藏在附录。

实质取舍给出真实候选、各自代价、建议依据和期望回复；无新增待决明确说明，适用的既有决定直接引用。业务名称优先，长行为和复杂决定用记录卡，ID、精确版本和逐项检查放追溯附录。未知规则在正文对应位置标明并返回业务建模。交付前检查：不翻附录能否看懂本期做什么、正常操作会怎样、出错后怎么办、需要拍板什么；摘要和正文必须来自同一功能及规则版本。

## 保存、检查与交接

FUN/PAGE/适用 NFR 经共享 put 保存；T03 按[审核材料登记规范](../../references/registered-review.md)使用 review_bundle 提交，以 put 返回的 path 打开版本正文。按需新建 `03-产品方案/页面布局/` 和 `03-产品方案/粗原型/` 保存版本化附件；已有英文项目沿用原布局，以脚本返回路径为准。定稿时在同一次 put 中登记布局、HTML、实测记录及本地依赖；正文给出可打开入口、版本与操作说明。不要新增成果类型或把 S3 功能验证原型登记成 S4 的 P04。refs 只引用实际使用的 T01/T02/SCN/RULE/FUN/PAGE 等确切版本；先保存上游条目再登记汇总，不虚构 ID 或制造循环引用。R03/D03/Q03 可作附表。

需要新产品取舍的条目用 `decision_roles:["product"]` 表达必要决定，记录真实批准；不需新取舍时复用适用授权。按 [质量与变更](../../references/quality-and-change.md) 保留历史、分析影响、复检；图示如有需要使用既有 [draw.io 规范](../../references/diagram-standard.md)。

Q03-01—06 保留原编号，检查业务覆盖、范围依赖、完整行为、权限路径、方案取舍及同版复检。核心正常、关键异常和适用权限/返回路径必须有浏览器实际操作证据；无法运行就记录阻塞，不能只检查 HTML 存在便通过。展示检查并入 Q03，按共享规范分别实测默认用户路径与评审模式，核对本期页面、导航、层级/反馈和适用视口；不能用控制台事件通过或手机外框代替产品任务通过。缺品牌素材不阻止有标记的统一演示样式。程序 gate 不替代语义核验，内部功能检查不冒充真实用户验证或品牌视觉通过；质量合格但缺批准保持待授权。仅在必要决定和版本都适用后 promote。

展示 T03 位置/版本、布局与功能验证原型入口、检查证据、实际决定、未关闭问题及 S4 接续建议；交接明确关键任务与区域、已确定的信息/操作/状态及来源、可自主设计的呈现和仍待处理的缺口，沿用布局记录，不另建重复台账。S4 优先复用同版方案与功能验证原型的适用界面、组件及已验证交互，再按正式要求细化视觉与交互、核验平台适配及开展真实用户验证，不能另起一套业务规则。产品经理实际同意继续后 handoff S3→S4，适用既有授权直接复用。每轮 checkpoint 到具体 A 步骤，等待时继续独立内容，不默认沉默为批准。
