# 平台准入与资质核查

2026-11-09 本地新增方法。用于 S1-A03/A04：业务粗范围可辨后、首期范围确定前，查清“这些内容由该主体在该平台/地区提供，需要满足什么条件”。后续新增业务也按影响重新进入。本环节提供有来源的准入建议；实际类目、备案、许可和审核由平台或主管机关决定。

## 何时执行与裁剪

新建对外产品、选择小程序/应用分发渠道、进入有经营准入要求的业务，先判断适用性再核查。用户已明确要求资质审核时直接执行。没有指定平台时，先按已知业务列出影响判断的平台/地区/主体缺口，可以比较有依据的条件分支，不擅自假定“社交”就是微信或所有主体规则相同。

用户只要求准入/资质核查时，复用已有粗范围和材料完成这一项，不重做整份需求定义或无关竞品报告。

已有产品仅改文案、布局或修复已定行为，且平台、地区、主体、业务内容与经营方式未变时，复用适用的已有核查，不重新扫描全部行业。纯内部系统不套用公开小程序类目；业务本身另有明确准入要求时仍核查相关项。没有当前触发依据时简述不适用理由即可，不生成空的核查报告或新的人工审批作业。

## 从想做的内容形成核查对象

从用户资料提取实际服务、平台/分发渠道、面向地区、运营主体类型与已知资质、经营方式。只追问会改变本轮结论的信息；主体未知时可先查允许的主体及其条件，不要求用户预先注册公司或上传全套证件。

不要凭“社交小程序”等产品名称匹配一个类目。按当前拟提供的能力分别判断，例如用户发帖/评论、陌生人或熟人私信、群组互动、婚恋服务、音视频等；这些是业务区分线索，不是预置的现行平台类目。只检查已提及或为当前任务所必需的能力，不将所有社交形态默认纳入。

多项服务可能涉及多个类目或附加条件。按实际功能取得官方当前的完整类目路径、适用范围和主体限制；找不到确切路径时写候选及待核实，不编造名称、编码或“不需要资质”的结论。

## 查询与证据

1. 优先查询目标平台的官方服务类目/主体范围/运营规范，以及实际主管机关的办事指南、法规或公告。使用现有检索能力，搜索后实际打开支持结论的页面；用户提供的官方后台资料核对来源和日期。其他平台的规则、商业代办页、旧转载和搜索摘要只作线索；地方或特定主体的材料要求不直接推广到其他地区/主体。
2. 记录平台/地区/主体、查询日期、来源标题及直接链接、规则生效/更新信息（能取得时）、支持条款的定位、实际访问结果和适用条件。发布时间、访问时间和用户材料取得时间分别记录，无法取得的日期不补造。
3. 必须分别判断：平台类目及开放主体、主体身份/认证材料、适用业务许可或行业资质、基础备案及上线运营前置。仅在本业务触发时展开；APP/小程序备案、网站备案、经营许可与平台认证互不自动替代，不将所有社交业务统一写成“必须 ICP 经营许可证”，也不由“不收费”推定所有许可均豁免。
4. 查不到现行官方要求、页面无法访问、需登录或资料冲突时，保留实际限制与可核实入口，指出哪些结论仍不能确定。可以交付已查清部分和候选范围；不得借旧文章、另一平台或竞品已经上线来证明本项目获准。
5. 平台要求与法规要求可能同时适用。分别说明要求的发出方、适用对象及结论；不同层次未必构成冲突。只有适用范围相同且结论冲突时才列待核实，不替主管机关解释或批准。

费用、办理周期和能否代办，仅在有实际官方依据且影响本期取舍时说明；不编造可获批承诺或固定时长。核查任务不自动授权申办、提交材料、接受协议或对外联系。

## 对照现有条件并给出可行动结论

使用[核查模板](../assets/templates/eligibility-check.md)，信息少时可直接在 T01 中写简短结论，无需独立报告。每项要求关联实际业务、适用主体和官方依据，对照当前材料的持有人、类型、覆盖范围及有效性（已提供且相关时）。用户说“已有证件”先记为声明；没有材料或公开核验依据时不写成已核验，更不能把没提供写成确定没有。

正文先给推荐和对首期的影响，再列必要项。结论可按业务分别说明：有依据可继续方案；满足前置后推进；当前主体/模式不适用；规则或材料仍待核实。这些是分析结论，不新增工具中的批准或有效状态。

- 已有条件与规则匹配：说明证据覆盖到哪里，仍不能承诺平台最终审核通过。
- 已明确的上线前置尚未完成：列补齐事项、责任人/待指派及完成时点；可继续需求和原型。只要前提明确、可行性有依据且范围取舍已实际确认，缺少上线手续本身不自动否定 S1 定义或 PRD 交接。
- 主体不开放、核心服务被限制，或关键规则未知会改变方向/首期：明确受影响范围及待决定事项，保持相关方案为条件草案；继续独立部分。提出补齐条件、真实调整业务能力或缩小首期等有依据的选择，不自行删功能或改换主体。

没有依据时不默认“不可做”，也不默认“可上线”。把用户间私信改名为客服、把 UGC 改名为资讯而保留原行为，不构成适用规则改变；调整建议要说明实际服务对象、发布权或沟通关系怎样变化，再重新核查。

## 融入原流程与后续变更

在 T01 范围/重要约束写一次准入结论及当前必要取舍；较长清单才用唯一附件，正文链接摘要。完整官方来源、检索和适用条件映射保存在 R01，取得的输入用 SRC/snapshot 保存；核查工作稿可作为 T01 的 evidence 附件，不伪装成竞品 RESEARCH，也不新增阶段/条目类型。Q01-01 查来源与时效，Q01-04 查范围与准入前提，Q01-05 查会改变方向的缺口及实际取舍，Q01-06 查版本和后续承接。

后续业务模型、方案、原型和 PRD 继承必要约束及上线前置，不反复复制整份核查表。平台/地区、主体、经营方式、实际能力、公开/沟通对象、所用规则或证件适用性改变时，复核受影响项，并按公共变更规范同步来源、结论和下游；不得把旧结论直接套到新业务。单纯文案/布局修改且前提未变可复用，不以每次改动重新全套核查。
