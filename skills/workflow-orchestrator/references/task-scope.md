# 按本轮任务控制工作量

先从用户请求、已提供资料和当前项目状态确定执行范围，再读取所需模板。这里约束执行范围，不新增项目状态、阶段或审批。

用户从新产品想法或新增需求启动工作流，或明确进入 S1 时，默认形成 T01《需求定义书》和独立《竞品调研分析报告》，并按原规范维护配套记录；用户无需再指定文档种类。启动时向用户说明既定阶段成果，只补问无法从已有资料确定且影响当前工作的业务信息或项目位置，不把“本轮希望产出什么”作为启动必答项。用户明确限定只做调研、检查、局部修改或试用时，按其范围执行；接续已有项目且目标范围未变时，按有效成果与 next_action 继续，不重新回到 S1。只有上下文确实无法判断要推进阶段还是处理局部任务、且不同选择会影响执行时，才针对具体歧义补问。

纯检查任务读取已有成果和适用决定，报告具体问题、依据及建议，不自行改写有效成果；用户另有明确修复授权时按授权执行。局部修改可能涉及重要规则、权限或业务结果，应按实际影响扩大必要分析；纯展示或已定行为修复不因此重做整套流程。

## 先做可试用的小修改

用户明确要试用草稿、修一个已有行为、比较局部方案或验证一条路径，且没有要求完成整个阶段/正式交接时，先完成该任务。不要为一次局部修改补造全套上游或登记每个页面。不得把实际业务范围改变或正式交付请求自动降为小任务。

1. 先 discover；已有项目读 resume，核对本次涉及的来源、有效版本与限制。没有项目时可在用户指定的输出位置保存独立草稿，不必先 init/new 五阶段计划。读取本阶段基线中适用的行为/检查要求，按任务加载原型规范等必要引用；不先通读所有模板。仍须保留原始输入及来源，原件不覆盖。
2. 优先修改现有原型的工作副本，实际打开后沿同一用户任务修复。范围仅涵盖本轮行为和相关影响，别把四页小修改扩成重新设计系统。若会改变规则、权益或授权边界，先按原规范核实；未决部分可展示明确标注的候选，不能当企业规则。
3. 最小可审阅成果为：**可打开的本轮成果＋简短说明＋实际检查记录**。说明包括改了什么、沿用哪版/哪份输入、怎么试、预期结果、已测/未测、确需人决定的事项。说明与记录可合并在一个文件；页面布局可写在同一说明中，无须为每页或每种过程台账另建文档。若用户本轮明确要完整 T01—T05 或 PRD/SRS，则仍保留其既有结构。

   需要一个起稿格式时可选用[改动与试用记录](../assets/templates/change-review.md)；已有说明已覆盖这些内容就直接复用，不额外创建重复文件。
4. 现有登记版不可覆盖。小修改可先保留独立工作稿；涉及当前有效成果的变化，在已有项目 checkpoint 记录草稿位置、来源版本、受影响范围和下一步，不能暗中让工作稿取代有效版。待需要登记正式候选或阶段交接时，再按共享 put/review_bundle 建立所需条目及同版附件。
5. 在成果页及回复中分开写：**本轮任务实测结果**、**阶段生效/交接条件**。例如“返回后草稿恢复：实际通过；正式 S3：尚未核对有效上游，未申请生效”。局部试跑不提交整阶段 `I=pass`；也不为仅说明尚未开展正式评审而机械登记整阶段 `I=fail`。真正测到的缺陷照实报告，已有失败记录不抹除。正式 I 检查仍覆盖原 Q 编号和全部适用项。
6. 给出一个实际可用入口与代表任务。已有管理入口在登记后自动更新；尚未登记时直接链接草稿。不要为了统一入口再复制一套正文、原型或伪造已登记状态。缺正式批准不妨碍已授权的独立草稿工作，但不能据此 promote/handoff/deliver。

S4 的视觉材料 ready 核验仍在开发前执行，小修改只复核其实际影响范围，不能用“试用”绕过资料准入。品牌评审、平台适配、真人验证结论各自报告；未做就是未做，不从局部功能通过推导整阶段通过。S2/S3 按[原型展示规范](prototype-presentation.md)提供接近 S4 展示质量的界面，继续分别验证业务与产品功能；正式品牌材料缺失不阻止有标记的演示样式，不将 S4 准入和评审提前。

## 要完成阶段或正式交付

用户要求完成本阶段、进入下一阶段、形成正式成果或交付时，执行该阶段完整的适用成果、质量、登记和交接要求。可直接复用本轮已做且版本一致的草稿和真实证据，补齐缺口；不重新做一遍已通过任务、不复制批准。关键内容缺失保持待补，只有缺实际授权时才称待授权。

AI 自行完成整理、命令维护、修复和复检。用户处理确实需要其核实的事实、业务取舍、真实用户安排及实际授权；不把执行范围选择做成每轮必答问卷。
