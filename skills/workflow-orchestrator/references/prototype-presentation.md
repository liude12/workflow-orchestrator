# 原型展示、平台适配与任务质量

S2 业务验证原型和 S3 功能验证原型（原称粗原型）默认呈现目标用户实际使用的产品：打开后有适合目标平台的入口、导航、业务页面和连续任务，展示质量接近 S4。审核人应能像使用 App、小程序或 Web 产品一样完成本期任务，而非操作一组功能演示控件。阶段差别在验证目的、方案确定程度和证据要求；展示完成度不能代替业务闭环、功能覆盖或真实用户验证。

本规范的平台覆盖、全局路径和任务产出检查也供 S4 引用；各阶段沿用自身质量编号、资料准入及验证边界，不因共用检查升级为正式阶段通过。

## 生成前确定呈现方式

优先复用已有产品规范、可用组件、资产及上游适用界面；先核对来源、适用范围和可复用部分。缺少正式品牌时，AI 根据角色、任务和设备自行形成统一的演示样式，标明“演示样式，非正式品牌标准”；不强制灰阶，也不为普通配色、字体、间距或布局选择新增人工批准。S4 的正式资料准入、独立成品评审及真人验证不提前成为 S2/S3 的启动条件。

在现有 T02/T03 原型说明或布局中先明确以下内容；可用短文或现有表格，不新增成果编号、重复台账或审批。新原型覆盖本期整体，小改动只更新受影响部分：

- 目标平台、使用角色和使用场景：按已有约束选择 App、小程序、桌面 Web 等交互方式，记录依据与目标视口；未定时说明初步假设及影响，不把所有产品强制做成移动端或管理驾驶舱。
- 产品入口与页面组织：各角色默认进入哪里、怎样找到任务、哪些本期页面/区域承接信息与操作、完成或取消后去哪里。S2 记录用于解释业务的场景界面假设；S3 关联有效 T03/FUN/PAGE，覆盖本期页面和任务，不只选几个功能演示。
- 连续任务与数据：用同一对象说明入口—操作—结果—返回/接续；多角色分别从各自适用入口接手，切换演练身份不重置业务数据。信息、权限和状态沿途一致。
- 首屏重点、信息层级、主次操作和反馈位置：采用符合平台与任务的布局和组件，字体、配色语义、间距保持一致。常规展示选择由 AI 自主完成，不机械限定主按钮数量、配色或装饰。
- 采用自包含 HTML 或按各阶段规范保存本地依赖。延续有效版本中的已验证交互，修改前判断影响，保留旧版并复验相关任务。

页面数量服从真实范围。即使本期只有列表与详情，也应形成可连续使用的小范围产品；不得为“像 App”擅加登录、消息、个人中心、新增/分配等业务，或放置无效导航。必要能力或页面缺失时回到对应上游补齐范围与方案；将模拟和未覆盖部分说明白，不能编造能力或以占位点击冒充实现。

## 默认用户界面，评审工具独立打开

- 默认打开当前角色的产品入口，展示其任务、当前对象、状态、可执行操作和下一步。业务操作必须能从产品页面完成；不依赖审核人去控制台选择事件才能推进正常任务。
- 角色/场景切换、故障注入、重置、负向测试、规则编号、资源前后快照和技术日志放在明确的独立评审入口，默认关闭。需要换角色时可从该入口切换后回到对应用户界面继续；评审工具不能假装产品权限或登录机制。业务用户本来就需要的信息仍按其职责显示，不因工具隔离隐藏必要状态或待决影响。
- 模拟数据、演示样式和外部处理边界在外部评审条或独立说明中清楚可查；避免用大篇 TEST 说明、教学步骤和调试设置占据产品首屏。相关业务步骤仍须明确模拟或待决定，不能藏入说明掩盖其结果。
- 布局、字号、分组和留白表达主次，控件名称与作用一致，长内容可读。给表格上色、加手机外框或换几个图标不能代替用户页面与任务体验。
- 正常、空、处理中、成功、失败、无权限/状态禁止、待决定等按本期业务适用性呈现；按钮可用性、校验、反馈和可继续路径与规则一致，不用装饰性的成功提示代替状态变化。
- 用户界面按角色和状态呈现适用操作；另从评审入口实测非法/重复/越权等负向动作及业务守卫，不得只靠隐藏或禁用按钮跳过拒绝检查。未知规则继续显示待决定并保留原业务状态及关联资源，不能为演示顺畅采用候选规则。
- 按目标设备检查布局，并对适用窄屏检查导航、区域顺序、文字换行、溢出与控件可操作性；明确仅演示或尚未验证的视口。某个视口显示正常不等于全平台适配通过。

## 目标平台与页面、视口覆盖

已确定面向手机 App 或小程序时，以手机端作为设计基准（mobile-first），先确定手机上的信息顺序、导航、触控和返回，再扩展其他适用视口；不能把桌面缩小或加手机边框当作适配。桌面工作台等产品按实际使用平台设计，不普遍强制移动优先。

生成前在现有设计记录中列出“页面/任务—视口及输入方式—关键状态—检查点”。每个本期页面在目标主视口有查看与操作安排；根据内容密度、弹窗、长内容及布局变化，选择适用的窄、常规、较大尺寸补测，并给出选择依据。共用布局/组件可复用同版证据，写明覆盖关系和差异；不机械测试全部组合，也不能以首页或一个 390 px 视口替代全部页面与平台。

检查点按任务适用：文字与长内容是否可读、是否非预期横向溢出；空/错误/结果状态有无截断；关键触控区域和相邻操作是否可区分、是否依赖悬停；滚动到底后内容和操作能否到达、固定区域是否遮挡；产品返回是否保持应保留的对象、筛选或输入。需要查看细节的图表/图纸等检查其实际放大和恢复方式；需要保存/下载的任务检查从结果页能否找到入口并得到预期内容。按既有平台规范核对尺寸，不把某个通用数值变成全部产品门槛。没有相应功能则记录不适用依据，不为凑检查新增能力。

分别记实际浏览器、视口、鼠标/键盘或触控模拟，以及原生容器/真机环境。浏览器窄屏和设备模拟的结论仅覆盖已观察的网页行为，不能写成微信或原生真机通过。依赖容器返回、系统权限、软键盘、安全区或文件保存等能力时，列明实际执行环境与仍需原生/真机核验的项目。

## 首次走查的输入、产出与全局路径

在首次操作前，从有效需求、规则和产品方案选代表性输入并约定结果判据。样本覆盖典型任务及会改变结果质量的已知差异，例如内容长度、复杂度、合法边界或失败条件；数量随风险选择，记录选择理由，不仅采用最容易成功的演示数据。原型不支持输入变化时，可在隔离副本更换明确的静态样例后重新打开，保留样例与版本；设置样例不能代替用户操作。

对每项核心任务，说明用户最终要使用的产物是什么，可能是记录、状态、清单、图像、文件或交接结果。约定：内容是否正确完整、是否适合后续用途、是否满足适用领域/平台/材料约束，以及有无明显的额外整理、反复录入或准备负担。判据要有来源、能从样例和实际结果核对；领域事实不足时列为待核实，不临时发明质量阈值。无独立文件产物的任务仍核对结果状态和后续使用，不强加图像、色板等领域字段。

首次走查同时从默认产品入口覆盖各本期核心路径，包含并列路径及必要的角色入口，走到结果并返回/接续；不能等局部功能优化后再补全局产品检查。两页产品也可形成完整系统，不强加首页栏目或不在范围内的页面。评审工具只用于设置前提或负向检查，不能替代正常任务入口。

操作后将实际产物/状态与输入、判据和后续用途逐项对照，记录例子、差异和证据；按钮响应、成功提示或文件可下载不等于产出合格。实际使用负担可先记录可观察的额外步骤、碎片数量或手工修正等，但不能据内部走查宣称真实用户满意。算法、外部响应、数据或材料为模拟时，明确已实现和未实现的能力、模拟产物能检验什么；不能用固定样图或模拟成功证明真实生成、正式色值、实际材料或生产能力。实际领域验收与真人验证依原要求分别保留。

## 保持阶段职责并延续成果

| 阶段 | 展示内容与确定程度 | 必须另有的验证证据 |
| --- | --- | --- |
| S2 | 用完整用户场景界面解释和操作业务，不能以业务阶段为由只交事件控制台；界面及导航是演练假设，不自动成为产品方案，也不提前要求 FUN/PAGE | SCN/RULE/流程节点到各角色用户入口、实际事件、交接、对象状态和关联资源结果的证据 |
| S3 | 按有效 T03、FUN/PAGE 形成本期可连续使用的产品系统；复用 S2 中适用界面和组件，重新核验产品组织及全部本期功能/页面覆盖 | 业务任务/规则到 FUN/PAGE、产品页面操作、可观察结果与返回/接续的实际证据 |
| S4 | 优先复用上游适用界面、组件和已验证交互，在资料准入后按正式要求细化；演示样式不能自动视为正式品牌标准 | 既有 Q04、独立成品评审、任务走查、平台适配及真人验证的各自结论 |

## 实际检查与留证

在原 Q02/Q03 内分别记录以下实际结果，复用同一任务与证据，不新增门禁：

1. 默认用户模式：评审工具关闭，从产品入口找到并完成核心任务，核对结果、返回及下一步。多角色任务仅在换身份时使用评审入口，各角色处理仍在其产品页面内完成，同一对象连续保留。
2. 评审模式：触发必要异常、负向动作及未知规则保护，核对前后状态、资源与日志；不能用这一模式的事件按钮通过替代用户路径通过。
3. 呈现与范围：查看默认入口和核心过程/结果状态，记录截图、实际浏览器/视口、导航/层级/反馈及适用窄屏问题；反查本期页面覆盖与无依据新增。按钮数量、截图、套壳或视觉整洁不能证明产品体验完整。
4. 平台覆盖与产出：按上述页面/视口计划核对实际覆盖，以代表性输入对照任务产物判据；记录通过、不通过、未测试或有依据的不适用，以及模拟/原生/实物边界。复用已有同版任务步骤和截图，不另建重复台账。

未执行写未测试。发现正常任务依赖调试控件、页面断开或入口缺失，先修复方案及实现，再复验受影响任务。展示、业务/功能、正式品牌与真人验证各自有依据，内部操作不能代替后两者。
