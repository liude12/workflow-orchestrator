# 成果与记录数据规范

## 编号与文档头

T01—T05 是五份阶段成果类别，P04 是交互原型。R01—R05 是过程台账，D01—D05 是决定，Q01—Q05 是检查；可为成果附表，不需要逐条独立成册。

S2 将可交互业务验证原型、场景操作说明、实测记录和正文引用的图表登记到同一版 T02。正文链接原型和实测记录。实测记录标明对应的 SCN、RULE、流程节点及版本。T02 的 refs 指向实际采用的需求来源、场景和规则。

S3 将系统页面布局、可交互功能验证原型和业务功能覆盖实测记录登记到同一版 T03。布局可写在正文的明确章节，也可作为链接到的独立文件。T03 的 refs 指向上游业务及 FUN/PAGE。S2、S3 都通过 put 的 review_bundle 保留文件之间的相对路径并登记哈希，另有原始输入或确认记录时可独立 snapshot。字段和示例见[审核材料登记规范](registered-review.md)。

S4 在有效 T03 及其附件上打磨，P04 绑定生成后的 HTML。资料准入、品牌对照、独立评审及整改证据随对应 P04/T04 版本记录。

S5 默认把 PRD 正文和 SRS 详细规格作为配套双文档交付。PRD 为 T05 正文，SRS 经 review_bundle 以 srs 角色登记，同版保存相对链接与哈希。FR、QR、CON、INT、QLT 等读者编号在追踪表映射到实际 REQ、AC、RULE 等记录及版本。两份文档共用待决编号，规格修改触发同一 T05 的新版本与影响核对。[双文档写法](../stages/prd-authoring-and-review/references/prd-srs-writing.md)

条目采用项目或需求短代号—类型—流水号，类型包括 SRC、PROB、SCN、RULE、FUN、PAGE、TASK、EVD、REQ、AC、DEC、ISS。版本独立递增；删除和替代保留历史关系。REQ 指 PRD 需求，不混用为 T01。

RESEARCH 是 S1 独立竞品调研报告的实现类别，不替代 T01 或 R01/D01/Q01；EVD、DEC、ISS 为证据、决定和问题的记录标识，通过 evidence/record/question 等记录，不表示均可用 put 创建。put 支持的类型以共享脚本 TYPES 为准。

成果文档头：成果名称/标识、项目、目标版本、成果版本、状态、责任人、来源成果及版本、必要决定、质量结论。正文引用条目 ID、确切版本及位置，允许多对多；不适用关系说明理由。

## 状态与版本

工作稿、候选版、当前有效版、历史批准版分别处理。有效状态须质量通过且必要决定、验证和授权适用。历史批准不保证当前目标有效；没有有效版时显示空缺及原因。

中文状态为处理中、待质检、质检不通过、待人工决策、待授权、待授权复核、待更新、有效、已替代。内部存储字段可归纳状态，但导出的含义不能混淆质量结果和授权情况。latest_version/current_valid_version/last_approved_version 分别定位最新、有效内容、最近历史批准版本。角色调整不改未变内容版本；撤权影响的审批/人工复核/委托/豁免/交接按当前职责动态核验，可能保留内容指针而不能复用或交付，须看 gate/resume 的具体原因。相同角色配置不变更记录，新增兼任不自动使上游内容失效。

历史版本仍在有效内容引用闭包且原授权因职责变化失效时，受限的 `authority_rechecks` 追加当前有权人的 V/approval/validation 补核，绑定原 id/version、类别、原因及前后证据。原历史正文和记录保持不变；补核参与清单及适用性检查，不能据此修改历史范围或绕过必要新交接。具体登记见[本地命令](local-tools.md)。

交付状态另行记录：exported 为已导出、待包内检查；delivery_failed 为交付验收未通过；delivered 为包内验收完成。delivery-check 将实际操作证据绑定交付编号、manifest 哈希及包内入口，记录在管理状态，不修改获批包。旧 delivered 若没有验收记录，读取时按待检查呈现；包或证据后来变化时按验收未通过呈现。它们不改变各成果的业务批准或真人验证结论。

## 记录最低字段

- R：编号、来源位置/日期/版本/原文、事实状态、缺口或冲突、影响、阻塞性、处理与责任人、关闭依据。
- D：事项、候选、推荐依据、实际决定、来源与日期、决定人及权限依据、适用版本/范围、回填位置。
- Q：检查编号、对象及输入版本、实际证据、通过/不通过/不适用及理由、问题等级、修正与责任人、复检结论；内容与生效核验分开。
- 问题：证据、来源阶段、影响成果、是否阻塞、建议、决定、处理人、关闭证据。
- 交接：来源阶段/目标阶段、成果版本及位置、来源、必要决定、检查、未关闭问题、下一步、产品经理继续决定及出处。

程序具体 JSON 输入按 local-tools.md；台账语义字段可放正文或 conclusion/criteria 中，不能用技术字段齐全代替事实充分。
