# draw.io 图表规范

适用于业务流程、泳道、状态及工作流架构图。图表用于解释和核验相应业务，不把每个步骤机械转换为页面。是否需要独立图按复杂度决定；需要交付的图统一保留可编辑 `.drawio`，重要图同时提供 SVG 或 PNG 供文档阅读。

## 编号、语义与可编辑性

- 图源必须包含真实的节点、连接、文字和几何信息，可在 draw.io 中继续编辑；把整张图片放入一个节点不等于可编辑流程图。可直接生成合法、未压缩的 `mxfile/diagram/mxGraphModel`，再用实际 draw.io 检查。
- 业务图引用实际 SCN/RULE/对象编号及版本，步骤可用 `<SCN-ID>-N01` 等稳定编号；相同编号在 T02 文字、推演路径和图中表达同一动作。图的内部 cell ID 可复用业务步骤编号，便于定位。
- S1—S5、Sx-Bxx、Sx-Axx 是协作阶段/业务节点/AI 步骤编号，只在表示这套协作工作流时使用；产品自身业务步骤不要误编号为 S2-A03。T02 等成果编号也不替代产品业务步骤编号。
- 泳道标实际业务角色和交接，连接方向明确，分支边写可判定条件。图中起点、终点、状态转换、交付物与文字一致。重要图附场景/规则版本和图例。
- 企业规则未知时明确标注待决，使用候选说明或虚线注释区分；不能把推荐方案画成无条件生效的处理。颜色可辅助，但不能仅依赖颜色表达是否确认。
- 只使用需要的图形和可读字体，避免文字溢出、连接穿过文字、裁切、关键分支缺标识。状态转换需有事件/条件/角色；泳道交接需有接收者。使用 BPMN 名称时遵守实际采用的符号语义，不将普通流程图冒称完整 BPMN 模型。

可从 [S2 最小泳道模板](../stages/business-modeling/assets/templates/business-flow.drawio) 起步。它包含明确标注的 TEMPLATE 内容，不是业务事实或测试通过的样例；使用时替换角色、节点、边条件和版本注记，也可从空白图开始。

## 文件位置、版本与证据

新业务项目内使用以下中文路径；接续已有英文项目时按其已识别布局保存，不为命名变更另建一套目录：

```text
02-业务建模/业务图表/<SCN-ID>/v1.drawio
02-业务建模/业务图表/<SCN-ID>/v1.svg
02-业务建模/业务图表/<SCN-ID>/v1.png     按阅读/检查需要选择 SVG 或 PNG，不强制两者
```

多页重要图用 `v1-p01.svg`、`v1-p02.png` 等区分。图 ID/版本独立记录在 T02 的图表表中，同时列明源文件、导出物、对应场景/规则版本和证据定位。实际文件名以项目约定为准，禁止仅凭名称判断当前有效版本。

编辑工作稿与已登记版本分开。业务文字或规则修改后，检查图的节点、条件和状态是否受影响；需要变化则创建新版本，保留已确认旧源和旧导出。不能只改 PNG/SVG 留下旧图源，也不能只改图源继续引用旧导出。

图源与导出物标明对应图页、cell 或节点，规则另附业务来源和决定依据。保留实际打开、导出和查看的操作记录，供 Q02 核验。

T02 通过 put 绑定 T01/SCN/RULE 等实际 refs。将审核正文或实测记录引用的图源与导出图作为 support 文件随同版登记，交接前从登记版正文打开核对。原始图表快照可以按来源或变更审计需要另行保存。[审核材料登记规范](registered-review.md)

## 实际打开、导出与验收

生成源文件后执行以下实际检查，不把 XML 语法通过当作图已验收：

1. 用当前安装的 draw.io 打开该源。可以使用桌面编辑器；也可用 draw.io CLI 实际读取并导出未压缩 XML，证明工具能重新解析图源。记录所用方式、工具版本（可获得时）和结果，不把 CLI 读取称作已在桌面拖动编辑。
2. 检查图页、业务节点、连接 source/target、分支条件及文字，和 T02、规则/状态、推演路径对照。CLI 往返时核对重新导出的 XML 节点和连接仍在，源不是单张静态图片。
3. 使用现有 draw.io 导出 SVG/PNG；记录实际命令或操作、输出路径和失败信息。多页图逐需要的图页导出，不能只导出第一页即宣称所有页完成。
4. 实际查看导出图像或浏览器中的 SVG，检查中文、连接方向、分支标签、边界裁切与图文编号。不能仅看文件存在、XML 解析成功或命令退出码。
5. 修正后重新打开/导出并查看受影响图，记录最新版本和 Q02 复检。无法使用工具或无法查看导出图时如实保留未执行范围及待检查状态，不假称完成。

本机 draw.io CLI 已有 export 能力。下列命令形状适用于 PowerShell；使用前确认当前可用可执行路径及其 `--help`，不要把示例当实际运行记录：

```powershell
& "<drawio_exe>" -x -f xml -u -k -o "<检查输出目录>/v1-roundtrip.xml" "<项目图源绝对路径>/v1.drawio"
& "<drawio_exe>" -x -f svg -k -o "<项目图源绝对路径>/v1.svg" "<项目图源绝对路径>/v1.drawio"
& "<drawio_exe>" -x -f png -k -o "<项目图源绝对路径>/v1.png" "<项目图源绝对路径>/v1.drawio"
```

`-k` 防止覆盖已有输出；更新时选择新版本路径。多页图可用已支持的 `-p <一基页号>` 指定页。CLI 导出是当前应用能力，不需要另建专用导出服务。若使用后台进程运行 CLI，按宿主工具要求隐藏辅助窗口；需要交互编辑时再打开可见编辑器。

验收记录至少包含源/导出版本、实际打开方式、图页/节点/边检查、图文一致性依据、实际图像查看结论和未关闭问题。工具检查证明文件可用，不替代业务规则批准或真实用户验证。

## 推演路径与连线核对

先从T02和实际场景推演提取预期节点顺序，再和图核对；不能反过来仅照现有图写“预期”，否则遗漏的路径不会被发现。可用只读 [inspect_drawio.py](../scripts/inspect_drawio.py) 输出节点/边并核对直接连线：

```text
python -X utf8 <skill_root>/scripts/inspect_drawio.py <图源.drawio> --paths <推演路径.json>
```

路径文件示例：`{"paths":[{"name":"未知结果转查核","page":1,"nodes":["SCN-001-N05","SCN-001-N10"]}]}`。使用实际节点ID，page从1开始。未压缩图源可直接检查；压缩或包装节点等不支持格式先用draw.io导出未压缩XML，或人工核对并说明范围，不绕过错误写通过。退出0表示给定路径与结构通过，2表示发现问题，1表示输入/解析失败。该工具不写文件，不证明路径覆盖完整、规则真实或图像可读，仍需按前述步骤导出查看与业务核验。

检查覆盖每页全部连线。业务边的起点和终点需要绑定本页的顶点单元（`vertex="1"`），含按顶点建模的泳道、嵌套节点和端口。错误结果给出图页、边 ID、端点方向和目标 ID，便于重新绑定。使用连线之间衔接、自由端点等特殊画法时，请在 draw.io 中核验并记录实际语义。
