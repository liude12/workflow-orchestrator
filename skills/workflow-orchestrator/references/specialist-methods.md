# 阶段内专业方法的使用与适配

总控与阶段 Skill 继续负责范围、有效输入、业务决定、质量与交接；以下方法负责具体分析或生成。它们随本包提供，有真实可读入口，不需要先安装整个上游插件。进入适用任务时读取并执行相应方法，小修改只做受影响部分。

## 选择方法

| 方法入口 | 何时使用 | 回填位置 |
| --- | --- | --- |
| [research-evidence](../methods/research-evidence/SKILL.md) | S1 独立研究的证据与反证核对；按需准备真实访谈或诊断模糊方向 | RESEARCH/T01、现有来源与问题记录 |
| [task-solution](../methods/task-solution/SKILL.md) | S3 新方案、复杂路径组织或功能实质变更；按需复用当前可用的用户故事/拆解方法 | T03、FUN/PAGE、页面布局与验收表达 |
| [scenario-coverage](../methods/scenario-coverage/SKILL.md) | S2—S5 有重要异常、多对象结果或变更影响需要独立查漏 | 原有场景、AC、Q02/Q03/Q04/Q05，不新建用例编号体系 |
| [prototype-build](../methods/prototype-build/SKILL.md) | S2/S3/S4 新建原型或实质修改；小变更沿用设计与交互 | T02/T03 的原型附件；S4 的 P04/T04 与 Q04 |
| [capability-specification](../methods/capability-specification/SKILL.md) | S5 复杂约束、已有系统契约、迁移或必要的详细规格展开；也可核查已有规格 | 同版 SRS、REQ/AC、待决项和 Q05 |

这些是本工作流的适配方法，名称与上游区分。实际使用记录写本地方法名；不能将执行它们写成已调用 ECC 原命令、已运行外部插件或已完成真人验证。[来源与改动说明](../methods/provenance.md)

## 一次使用如何执行

1. 由阶段入口明确当前任务和触发原因，复用有效资料的确切版本、已有决定、已有成果和未决边界。资料充分不重复访谈，不要求用户选择模板或重新填写已知信息。
2. 读取选中的本地方法，再执行适用步骤。方法建议的结构、数量和审美服从实际任务与项目规范；未知业务规则回来源阶段。常规表达、布局和设计选择由 AI 自主完成。
3. 将分析、页面或规格写回表中对应成果。复用既有稳定标识和单一有效规则，保持原模板与版本体系。保留旧版；新增业务承诺先完成来源阶段修订，再改下游并复验。
4. 在现有来源、变更或 Q 记录附一条使用说明：方法及版本/入口、输入基线、本轮范围、产物位置、实际检查与限制。可用[简短模板](../assets/templates/method-usage.md)，已有记录足够就不另建文件。模板填写和方法读取本身不能记成产物通过。

## 可选外部能力

- 当前会话实际提供 `user-story`、`epic-breakdown-advisor` 等时，可用其适用部分帮助本地 task-solution；先读说明并套用本地阶段边界。缺少入口时执行随包方法，不要求接收方具备作者机器上的路径。该包不附带这些第三方原文件或其全部依赖。
- 有选定图片或 Figma 文件时，prototype-build 才路由到当前可用的 `image-to-code` 或 `figma-design-to-code`。先核对目标、依赖、运行与交付载体；不能借此自动改变 HTML 交付或重新搭建整个系统。若用户指定外部工具而它不可用，报告受阻部分，不冒充已完成指定工具操作。
- `audit` 用于需要的体验复核；浏览器自动化用于稳定路径回归。已有浏览器能力可直接实测，不为名称额外安装测试框架。独立品牌审核、实际交互与真人验证仍分别记录。
- 在线发布、外部资料服务与实际用户联络按用户授权范围执行，不由本地方法触发。完整设计探索仅在任务需要时开展，不把固定多方案选择加入每次修改。

## 必用命令与缺依赖

S5 的 `/ecc:plan-prd` 是用户明确要求的外部生成入口，继续遵循[专门规范](../stages/prd-authoring-and-review/references/ecc-plan-prd.md)。本地 capability-specification 不替代它。缺少真实命令时，可以整理输入和核查既有文档，不能绕过后声称完成新生成。命令未执行、执行失败和部分完成分别保存。

可选外部辅助缺失时，继续执行适用的随包方法并如实说明所用入口；随包方法自身缺文件或校验不一致时，先修复安装或记录受影响部分，不能声称已执行缺失方法。发布与环境迁移可用[方法包检查工具](local-tools.md#专业方法包检查)核对文件与来源声明。检查只证明包结构及指纹，不判断分析、原型或规格质量。
