# 质量与变更

本阶段 Q01-01 至 Q05-06 及 Sx-Axx 溯源沿用本次 v1.1 基线。所有适用核心项逐项记录证据、结果、问题和复检；不适用需理由，未执行不能计通过。内容通过与生效条件分别检查。

S1 核对来源、用户问题、目标、范围、决定和版本；S2 核对场景、闭环、规则状态、异常和业务决定；S3 核对业务覆盖、依赖、功能行为、权限路径和取舍；S4 核对实际操作、方案一致、真实验证或豁免、反馈和版本；S5 核对上游、追踪、规格、验收、评审和交付。

## 变更流程

1. 保存变化来源、原因、作用版本和条目，判断源头：目标范围 S1；业务角色/规则/权益/状态 S2；能力行为 S3；展示交互 S4；文档引用/表达/验收 S5。
2. put 生成新版本，保留历史正文。分析直接及传递关联，并查找未显式引用但可能冲突的同义规则。不能自动把所有阶段全部重做。
3. 影响待分析期间暂停相关正式交接。确认有影响后标记待更新并修订；确认无影响时用 impact 记录具体理由、适用范围及证据，保留可复用成果。无影响不是笼统勾选。
4. 修订后重检受影响项；现有决定、质量和验证证据须检查是否仍适用，不替人重新批准。仅缺批准不重新生成成果。
5. 恢复历史版本也作为新操作记录理由、目标适用性与检查结果，不删除之后的事件。

一次反馈以完成受影响工作为收尾：回写来源及相关文档、布局和原型，实际复测受影响任务，维护版本与当前阅读入口，再向用户交回结果。补充决定若改变内容，应回到对应成果修订复检；仅补适用决定而内容未变，不重写成果。`put` 会清空新版检查与批准，执行者应逐项判断旧证据的范围并登记适用依据，不把清空记录本身当成必须让人重答。没有真实适用依据时才提出新的具体请求。

## 门禁与交付

gate 检查记录及引用，promote 标记条目有效，handoff 记录产品经理确认继续。三者含义不同。阶段报告包括成果位置/版本、实际质量证据、已确认决定、未关闭问题及下一动作。

S3—S5 按场景检查非功能要求：权限、数据含义、规模、恢复、兼容和可访问性；指标来自依据，缺阈值标待决，不编造承诺。

S2 在原 Q02 编号下增加业务验证原型的实际操作：从 T01 范围和业务模型准备正常、关键分支及适用异常，关联角色、SCN/RULE、流程节点、对象和资源结果，不能只从已有按钮反推覆盖。未知规则相关操作显示待决定并保持已知业务状态，不把候选推荐自动执行；工具不可用保持未测试。原型实测属于内部核验，不能替代 RULE/T02 的真实业务责任人复核与规则决定。规则变化须同时判断图表、业务原型及下游功能方案的影响。

RULE/T02 的真人复核由本需求登记的业务责任人执行。业务责任人明确委托其他已登记人员时，在该版本的 V 记录附委托人、受托人、成果编号、版本和真实委托依据。记录与后续 gate 都复核这个范围及证据。RULE 的业务决定仍由有相应决定权的人登记。

S3 在原 Q03 编号下检查系统页面布局和功能验证原型：逐条将 S2 场景、规则、状态及异常映射到功能、页面操作和可观察结果，保留浏览器实际操作记录，反查无来源扩项。S4 在原 Q04 编号下增加两道检查：A01 复用可选 UI/UX 资料，没有时由 AI 形成具体暂定设计基线，不强制补交或追加常规设计批准；仅实际必需品牌要求、规范冲突或上游缺口阻塞相依范围，设计依据 ready 后开发；A03 生成后以冻结材料包调用无开发上下文的 UI Finish-Gate Reviewer。

S2—S4 用原有场景/任务编号或可定位名称持续追踪业务意图，保持预期业务结果可比较。若材料说明用户会间断补录、离开返回或跨人接手，就在已有操作记录中验证同一对象、输入保留和最终提交；不把“按钮存在”当成任务完整。已有产品先实际查看当前页面及可用入口，核对复用能力、布局继承与删除页面后的承接。范围不涉及这些情形时不强加测试或新功能。

视觉评审只输出“结论 / 意见”，结论分功能、品牌视觉、平台适配、用户验证四类，给出证据及适用范围。go 直接通过视觉成品评审；no-go 按意见修正后重新独立评审，不设轮次上限，实际缺资料或工具时保留待处理；conditions-go 执行本轮修改一次，由执行者核对原条件已落实后通过，不发起新专家评审或增加意见。未落实不能称通过。新范围或新标准另立版本。正式品牌样式、明示临时样式和有意偏离及其理由分别记录。

[视觉评审记录校验工具](ui-finish-gate-tool.md)只核验结构、文件哈希与分支，不证明实际看图、上下文隔离或设计质量。原 workspace.py 的 gate 不自动检查这些语义，执行者须把真实评审与整改结果纳入 I/V/Q。视觉 go 不等于功能完成、平台外范围适配、真人验证或阶段交接授权，A05 的真人验证/有效豁免仍独立执行。

T05 可以提前积累草稿，正式定稿时核对适用上游成果的有效版本、跨角色评审和阻塞意见闭环。适用原型应和验收版本对应。已有不适用决定时核对其范围与依据。产品经理确认 S5 交接后，展示 manifest 清单，核对或取得交付负责人对此清单的批准，再执行 deliver。导出后按实际包内入口完成检查并用 delivery-check 登记操作证据；待检查、验收失败、验收完成分别呈现，包内检查不代替真人验证。外发和上线依对应任务授权执行。
