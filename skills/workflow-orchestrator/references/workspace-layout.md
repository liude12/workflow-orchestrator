# 项目定位与目录

从用户明确路径或当前工作目录开始，discover 的搜索范围必须有限且与任务相关，禁止遍历用户磁盘寻找产品项目。只认合法状态文件与项目标识，不能只认文件夹名。

- unique：读取路径、产品名、schema 及 resume，确认与用户任务一致后接续。
- none：用户已给名称和路径则初始化；否则集中询问缺失信息。初始化不是根据产品想法偷偷选择保存位置。
- multiple：展示候选，等待选择，期间可整理不依赖具体项目的资料。
- legacy：保留旧 state.json/items/evidence；预检迁移并在完整备份后转换。不可误判为空或覆盖原有状态。
- 损坏或不支持的状态：报告定位与原因；不能按新项目重建。

新项目默认使用中文业务目录：`00-项目资料`、`01-需求澄清`、`02-业务建模`、`03-产品方案`、`04-原型验证`、`05-PRD交付`、`06-项目管理`。项目根文件夹也可以使用中文名称。正文按成果稳定 ID 和版本保存；各阶段索引可定位历史。

| 业务目录 | 主要子目录与文件 |
|---|---|
| `00-项目资料` | `项目基本信息.md`、`原始资料`、`参考资料` |
| `01-需求澄清` | `竞品调研`、`需求分析`、`需求定义` |
| `02-业务建模` | `业务模型`、`业务图表`、`成果记录`；按需创建 `业务原型` |
| `03-产品方案` | `产品规格`、`成果记录`；按需创建 `页面布局`、`粗原型` |
| `04-原型验证` | `交互原型`、`验证记录`、`成果记录`；按需创建 `视觉标准`、`视觉评审` |
| `05-PRD交付` | `PRD文档`、`成果记录`、`交付包` |
| `06-项目管理` | `state.json`、`证据资料`及中文管理视图 |

`06-项目管理/state.json` 为新项目的唯一元数据来源；`项目状态.md`、`项目版本记录.md`、`成果版本清单.md`、`变更记录.md`、`影响分析记录.md`、`阶段交接记录.md`、`待决事项.md`、`质量检查记录.md` 是可重建视图。`state.json`、交付索引 `delivery.json` 和成果的 `<ID>/v<N>.md` 保留机器标识。恢复以状态索引和其引用文件为准，不根据某文件名称猜“最新版”。

`查看与试用.html` 是同一管理目录内的固定阅读入口，由维护工具写操作或 `views` 自动重建。它按需求列出已登记的阶段主文档、同版原型、操作记录、页面布局与 SRS，并区分当前有效版与候选稿；复用按计划指定版本显示，不自动换成别的需求的最新稿。正文及文字附件提供页内便捷预览，保留原稿链接；复杂排版按文字呈现，正式内容与格式以同版原稿为准。缺失或已改变的文件不提供有效链接或预览，质量与授权证据失效时提示待核对。该文件只是导航，不能成为另一套状态或批准依据；工作稿尚未登记时，直接提供本轮实际工作稿入口。正式交付仍从获批包内入口操作，不把可变项目导航当成包内入口。

已有 `06-project-management/state.json` 的英文布局项目自动按原布局识别和接续，新增版本、快照、管理视图及交付也沿用原路径；不因本次命名偏好迁移或重命名已有成果。根目录旧格式 `state.json/items/evidence` 按 migrate 预检与备份后迁移，保留既有正文/证据路径，新管理层使用中文。直接重命名已登记目录会破坏相对引用和快照定位，应由工具按真实状态维护。

产品文件不写入 Skill 安装目录。Skill 源码、测试案例和 TEST 项目与真实产品项目分开。具体路径和状态兼容性以 local-tools.md 及脚本 --help 为准。

辅助目录随阶段交付创建。普通条目正文通常位于 `<ID>/v<N>.md`。T02、T03 审核材料及 T05 配套 PRD/SRS 成套登记时使用 `<ID>/v<N>/`，其下保留本次工作稿的正文名称和附件相对目录。打开 put 返回的 path 或 resume 所列的实际路径。修订时另存新版本。初始化教学包应提供填写后的各部分样例。[审核材料登记规范](registered-review.md)
