# 公共模板索引

主文档使用[人工审核写作规范](../../references/review-writing.md)：审核摘要在前，业务内容居中，来源与过程记录在后。按真实问题填写，不把所有台账当成人工必读交付物。

初始化或整理项目资料时使用 [项目基本资料](project/project-info.md)；提交成果时使用 [成果文档头](records/artifact-header.md)；登记来源、决定、质量、版本、影响和交接时使用 [公共台账](records/management-records.md)。

局部修改可按需使用[改动与试用记录](change-review.md)合并变化说明与实测；已有记录足够时无需新建文件。

使用随包专业方法时，将[方法使用说明](method-usage.md)合并到对应成果或质量记录；实际触发、输入、输出和缺依赖处理见[专业方法接入规范](../../references/specialist-methods.md)，不增加审批或成果类型。

模板是填写约定，不表示已有事实、决定或检查结果。可合并为成果附表；只保留适用字段，不适用需说明原因。阶段专业模板由各阶段 Skill 链接。

S5 配套使用 [PRD 模板](../../stages/prd-authoring-and-review/assets/templates/t05-prd.md)、[SRS 模板](../../stages/prd-authoring-and-review/assets/templates/srs.md)和[需求对应表](../../stages/prd-authoring-and-review/assets/templates/requirements-traceability.md)，共同构成同一 T05 版本的可阅读交付材料。

前期统一补问用 [资料缺口与问题单](../../stages/requirement-discovery/assets/templates/information-gaps-and-questions.md)。S2 使用 [业务验证原型与实测记录](../../stages/business-modeling/assets/templates/business-prototype-and-coverage.md)检验业务闭环。S3 的系统布局和功能验证原型模板从 [S3 入口](../../stages/product-solution-design/SKILL.md)进入。S4 先用 [设计依据核验（UI/UX 可选）](../../stages/prototype-design/assets/templates/visual-material-readiness.md)，开发后用 [冻结评审材料包](../../stages/prototype-design/assets/templates/ui-finish-gate-packet.md)和[独立成品评审](../../stages/prototype-design/assets/templates/ui-finish-gate-review.md)，不要把准入和成品结论填在一起。

S3→S4 交接沿用 [页面布局](../../stages/product-solution-design/assets/templates/page-layout.md) 中的已定任务、信息、操作及展示选择。S4 ready 后用 [设计约定与映射](../../stages/prototype-design/assets/templates/design-contract.md)，自动核对的 JSON 示例及工具边界见 [页面结构规格](../../stages/prototype-design/references/page-structure-spec.md)。这些作为 T04 同版内容；局部修改只更新受影响部分，不增设人工审批。
