# 任务组织与功能方案适配方法

本方法依据本项目 S3 基线编写，默认随工作流可读执行，不依赖另一套 PM 插件。先遵循[专业方法接入约定](../../references/specialist-methods.md)，在本轮需要的方法中选择一项或组合，不机械重做完整分析。

## 选择本轮处理范围

| 发现的问题 | 采用的处理 | 完成判据 |
| --- | --- | --- |
| 功能列表零散，角色和入口之间接不上 | 按完整任务组织路径 | 从触发走到业务结果，并能返回或继续；每个交接有承接者 |
| 一个能力过大，无法独立验证或交付 | 按可完成的用户结果拆分 | 每个切片有明确边界、依赖及验收，保留所有适用强制规则 |
| 目标清楚但研发仍须猜操作后果 | 补全行为与可观察结果 | 同一条件下的输入、反馈、状态、权限及关联影响可判断 |

只改文案、间距等表现且不改变行为时，直接回对应阶段处理；已有图、功能记录和任务路径覆盖本次变化时，只修受影响部分。

## 输入与边界

读取本期有效 T01 范围、T02/SCN/RULE、已有 T03/FUN/PAGE、真实决定和待决，以及适用原型及实测。使用已有编号和确切版本；未登记材料注明状态，不生成看似有效的 ID。

已有问题答案直接采用并保留来源。需求范围变化回 S1；规则、状态含义或业务权限未知回 S2；S3 可以选择产品组织方式，常规展示细节留给 S4。以批准、计费、数据归属等强制控制为前提，不把它们当作随意删除的简化步骤。

## 组织连续任务

1. 从用户要完成的结果出发，列出触发、起始角色、输入或对象、结果及接续。优先还原材料中真实出现的任务；活动、步骤和页面数量服从本期范围，没有数量配额。
2. 沿同一个对象走完操作和角色交接。每步写谁接手什么、执行什么、交付什么结果，哪些由产品支持、人工负责或外部系统承担。外部处理至少有转出、等待/失败及接续说明；业务事实不足就保留缺口。
3. 映射到已有或拟定 FUN/PAGE：哪些能力共享，哪些信息出现在页面区域，用户如何找到入口，完成、取消或失败后回哪里。页面状态、弹窗和独立页面分别标注；不按业务步骤数机械创建页面。
4. 对照有效规则补齐适用分支和拒绝路径。不能为了让路径更顺而增加消息中心、登录、自动审批等未确定能力。发现缺失先列具体影响，交来源阶段处理。

采用[场景能力映射](../../stages/product-solution-design/assets/templates/scenario-capability-map.md)与[页面布局](../../stages/product-solution-design/assets/templates/page-layout.md)现有位置；复杂地图可作 T03 同版附件。每个关键任务均能查到来源、责任、功能/页面、结果与返回，不要求额外建一份台账。

## 拆出可验证的切片

1. 明确原能力的用户结果、必须成立的条件和本期承诺，再找可独立使用的任务、对象范围或已确认情境。切片大小以能否完整操作和判断结果为准。
2. 对每个候选写清纳入范围、明确不覆盖的情境、依赖、相关规则及可观察结果。检查完成这个切片是否仍需未交付能力，若需要则标依赖或调整分组，不能仅称“后续补齐”。
3. 强制审批、角色权限、资源释放及审计等有效要求在所有适用切片中保留。若现有范围无法在这些约束下缩小，明确最小完整范围；需要分期或改变承诺时给出选项与影响，沿现有产品决定流程处理。
4. 不把前端、后端、数据库等技术工作分层作为用户价值切片，不编开发排期或估时。两个候选没有实质差异时不强造多方案。

结果写入 T03 功能结构或既有方案比较记录；拆分关系关联原 FUN，沿用项目版本机制保留原版，不改变业务主记录。

## 补全行为和验收表达

按[功能行为模板](../../stages/product-solution-design/assets/templates/functional-behavior.md)给出角色、入口、前提、输入/校验、动作、系统反馈、结果和适用异常。用户价值可用短句表达，完整约束仍保留在行为记录中。

同一操作的对象状态、资源/权益、关联记录及用户反馈分别列出必要断言，允许一个场景有多个结果。不得为凑“单个 Then”删除断言，或把不可分割的原子业务结果拆成互不关联的故事。预期和阈值来自有效规则；未知结果列待决及影响，不用“正常”“正确”替代判定。

## 可选的现有专业方法

本轮若明确选择当前环境已有的 `user-story` 或 `epic-breakdown-advisor`，先从会话技能目录或实际安装位置找到并读取其定义，传入上述完整基线后执行适用部分。保留所选入口与版本/来源、实际采用范围和结果位置；固定数量、删除强制控制、无依据估时或反复询问已答信息不适用于本工作流。外部方法不可用时继续本文件的方法，不声称已调用外部 Skill。

这些外部方法不随本文件复制或分发，也不是本方法的运行依赖。来源与许可边界见[方法来源说明](../provenance.md)。

## 回填与核验

将任务组织、拆分理由和行为回填 T03/FUN/PAGE 及已有覆盖记录，注明本次实际执行 `task-solution` 的范围、输入版本、结果位置与未决内容。只读本文件但未处理任务，不能写成已完成方法执行。

从任务反查本期范围，确认没有无依据新增；从规则反查功能和操作路径，确认关键控制和关联结果完整。随后由阶段流程生成并实际操作功能原型。方法自检只证明方案核对，不能冒充浏览器实测、产品经理决定或阶段通过。
