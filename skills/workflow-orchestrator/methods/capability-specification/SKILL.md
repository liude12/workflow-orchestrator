# 能力约束与规格展开方法

这是基于固定版 ECC `product-capability` 的本地中文适配，来源与取舍见[适配溯源](../provenance.md)。它在现有 S5 内核查约束，不新增阶段、产品规划目录或成果类型。执行与记录遵循[专业方法接入规则](../../references/specialist-methods.md)。

## 何时使用

当本期能力涉及跨系统/多团队协作、历史数据迁移、角色和对象归属/权益、复杂状态转换与部分成功，或首次规格展开仍有研发必须猜测的约束时使用。已经清楚且简单的项目沿用 S5 基线即可；错字、链接、排版修复不触发整套方法。

开始前用一句话记录本轮要消除的具体不确定性。例如：“审批成功后才扣额度，而现有提交接口会立即扣额度；核对两个时点及失败恢复是否一致。”不要只重排现有 SRS 章节作为使用成果。

## 必用命令与有效输入

S5 新建或实质重生成 PRD/SRS 仍必须按[命令接入规范](../../stages/prd-authoring-and-review/references/ecc-plan-prd.md)实际使用 `/ecc:plan-prd`，或有覆盖本轮基线的适用历史执行。这个方法不能冒充命令、替代命令，也不声称命令直接产出 SRS。命令缺失/失败时可核查已有规格、整理输入和冲突记录，依赖命令的双文档生成保持未完成。

读取当前范围有效的 PRD、T01/T02/T03/P04/T04、SCN/RULE/FUN/PAGE/REQ/AC 和已确认决定，保留确切版本与位置。仅在现有项目确有相关材料时读取接口契约、架构/数据说明、权限策略、迁移规则、实际代码及外部依赖限制；记录真实来源，不把搜索到的通用方案当作现有系统事实。

PRD 说明要实现的产品承诺；已有代码/契约说明当前事实，两者不一致时应显式列冲突。现有实现不自动推翻有效业务决定，业务承诺也不能证明技术能力已经具备。未取得材料记未知及影响，不编造 API、表结构、授权机制或性能阈值。

## 1. 明确能力与本轮边界

用自然任务说明角色、要完成的工作、输入、可观察结果及成功信号，引用对应 PRD 功能和范围。列现有行为、本次变化及不在本期的能力；沿用原编号，不将建议扩展默认纳入范围。

首次展开可覆盖整个本期能力；增量修改只追踪受影响的规则、对象、接口边界、状态和验收，说明哪些历史结论仍适用。范围或产品目标发生实质变化先回 S1/S3。

## 2. 分清约束效力与冲突

逐项区分：

- **已确认业务约束**：有适用决定/规则的用户承诺、权益、状态含义、禁止副作用和跨对象不变量，引用唯一有效来源。
- **已核查现状**：实际系统、外部契约、数据和兼容条件的事实及版本；说明其证据覆盖范围。
- **实现建议**：为了实现约束提出的机制选择，注明依据和待评审范围，不把建议写成已批准架构。
- **待决或缺事实**：缺失、冲突、未知结果及受阻任务，沿用同一 DEC/问题记录和实际责任人。

对冲突写“来源 A 的条件和结果／来源 B 的条件和结果／影响对象与动作／需要形成的决定”。例如 PRD 要审批后扣额度，现有接口在提交时扣额度，应分别核对有效规则与接口行为、失败回补和重复操作；不能直接写一句“提交后正确处理额度”掩盖矛盾。业务取舍回 S2，功能路径回 S3，技术机制请实际研发核对；可自主修正文案和引用。

## 3. 按风险展开约束

只展开适用于本期的维度；不适用写依据，未知保持待决。

| 维度 | 要得到的可核对结果 |
| --- | --- |
| 角色、权限与信任边界 | 谁以什么条件读取哪些对象/字段、执行哪些动作；身份/组织/归属变化或授权过期的结果；外部结果的业务权威来源 |
| 状态与资源不变量 | 初始/结束状态、允许和拒绝的转换、时点、跨对象联动、额度或权益变化及禁止副作用 |
| 输入、输出与数据含义 | 数据来源与业务责任、单位/时区/标识口径、校验、可观察输出及后续任务用途 |
| 跨系统与失败恢复 | 交接方和接收方、已存在的业务契约、部分成功/结果未知/重复或并发变化的反馈、查询和恢复责任；未知处理不擅定 |
| 迁移与兼容 | 实际迁移范围、历史对象对应和重复识别、未知值处理、旧入口/账号/能力的延续、恢复要求与依据 |
| 质量与交付限制 | 适用的规模、性能、可访问性、兼容、可运维和发布约束及证据；没有已定指标时写待决 |

描述产品必须观察到的行为及外部交互边界，不要求产品经理选择数据库或具体协议。已有设计决定可精确引用；需要架构选择的部分标明责任和问题，不以原型模拟或建议代码证明生产能力。

## 4. 回填现有 PRD/SRS 和验收

保持十一章 PRD 与六章 SRS，按[双文档写法](../../stages/prd-authoring-and-review/references/prd-srs-writing.md)维护同一 T05。方法结果直接归入现有位置：

| 结果 | SRS 落点 |
| --- | --- |
| 角色、任务、输入来源、现状和成功信号 | 1. 能力概述 |
| 已确认不变量、约束效力、迁移/兼容要求 | 2. 约束与不变量 |
| 条件、输入输出、状态、权限、逻辑接口、失败恢复、质量和验收对应 | 3. 实现契约 |
| 本期与非本期边界 | 4. 范围边界 |
| 仍待业务/架构决定或缺事实的同一 DEC | 5. 待决事项 |
| 可交接范围、阻塞范围、来源和核对结论 | 6. 交接结论 |

采用现有 REQ/AC 追踪，不另建 PRODUCT.md、六段式替代正文或第二套状态台账。已有 SRS 已包含这些章名，方法的价值是查出并解决具体约束遗漏。PRD 保留产品承诺和重要取舍，SRS 展开已获依据的行为；新增业务规则先回源形成适用结论，再同步两份文档。

为关键正常、拒绝、异常、边界写明确的前置状态、输入/动作、可观察结果和禁止副作用，并关联实际 REQ/AC/规则版本。记录的是验收要求时写清“未实现/未执行”，不能因为条款详细就写成测试通过。测试无法观察结果时，提出需要的业务证据，交实际责任人确认。

## 5. 核对与交接

逐条反查本轮 PRD 承诺是否有 SRS 约束和行为，SRS 是否有来源，AC 能否判断对应承诺，涉及的系统/角色/状态是否存在遗漏或矛盾。复核当前代码/契约只是现状核查，最终产品需求须遵循有效决定。增量修改保留旧版并复核受影响追踪、原型及评审适用性。

将具体发现、来源、处理位置、实际查阅范围及未解决问题写入现有 R05/Q05 或 T05 附件。Q05-03 关注角色、条件、状态与逻辑契约是否可理解，Q05-04 关注异常/边界可验证，Q05-02/06 关注同版追踪及交付一致；不新增 Q 编号。

交接分别说明“当前可理解并可验收的范围”“仍需业务澄清”“仍需架构或现状核查”。这些是本轮内容结论，不自动代表真实多角色评审通过或交付已获授权。不自动启动 `/plan`、编码、架构或发布流程。
