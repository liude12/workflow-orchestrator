# 产品原型构建方法

这是工作流内部的中文适配方法。依据固定版 ECC `frontend-design-direction` 提炼生成前设计、状态覆盖、产品入口和渲染检查；来源与取舍见[适配溯源](../provenance.md)。使用本文件不等于调用原版 Skill 或外部插件。执行与记录遵循[专业方法接入规则](../../references/specialist-methods.md)。

## 适用范围与阶段目的

| 所在阶段 | 要验证的内容 | 方法落点 |
| --- | --- | --- |
| S2 | 业务规则、角色、状态转换、异常和业务闭环 | 用面向用户的完整任务呈现规则，写回 T02 和本阶段检查；页面表现是验证载体，不预先批准 S3 的功能方案 |
| S3 | 功能覆盖、全系统页面、信息层级和任务路径 | 依据 T02 实现应用入口、导航、跨页任务及返回，写回 T03、页面布局和功能覆盖记录 |
| S4 | 既定产品方案的具体呈现、交互和用户使用情况 | A01 ready 后落实 T04 设计约定及映射，写回 P04/T04/Q04；保留独立品牌评审和真人验证 |

三阶段均应像供用户操作的应用或小程序，不用规则表、孤立按钮或评审面板充当产品首页。S2/S3 可采用明确标识的演示样式；这不是正式品牌结论，也不免除 S4 的 VI/UI/UX 资料准入。新原型覆盖本轮任务；小改动只更新受影响部分。

## 先读取的有效输入

- 当前阶段、任务范围、验证目的、采用的 T01/T02/T03 与 RULE/FUN/PAGE/任务版本；只读取本阶段已经形成且适用的成果。
- 用户与设备、真实默认入口、必须完成的任务、信息含义、状态/权限、正常及重要异常的预期结果。行为不清回 S3，业务规则不清回 S2，目标范围不清回 S1。
- 已有原型、产品规范、组件、图标、资产及被验证的交互。记录可复用对象与版本，优先复用有效规范。
- S4 额外核对 [A01 资料准入](../../stages/prototype-design/references/visual-readiness-and-finish-gate.md)。用户 UI/UX 资料可选，未提供时由 AI 按有效 S3 形成具体暂定设计基线即可继续，不为常规设计新增批准。not-ready 仅阻塞实际受影响范围；既定品牌强制要求的偏离仍需适用决定，不能虚构正式标准。

## 1. 先确定呈现依据

在当前 T02/T03 的原型说明，或 T04 §2/同版附件记录：用户正在完成的工作、产品表面与设备、主要动作、信息先后、导航与返回、目标视口、复用规范及适用范围。S4 直接使用既有[设计约定](../../stages/prototype-design/assets/templates/design-contract.md)，不重复建立一套设计台账。

布局、密度、字体、色彩、主按钮和装饰均应服务实际任务。B 端高频工作、C 端内容浏览、手机小程序可以采用不同安排；没有固定配色、字体、按钮数量或“所有页面都手机优先”的规则。手机 App/小程序按目标手机任务设计。已有品牌或组件约定优先于外部方法偏好。

没有选定视觉参考时，依当前方案和规范直接设计并记录理由，不强制生成三套方案供人选。需要真实品牌或产品取舍时回对应决定，普通布局和视觉细化由 AI 完成。

## 2. 按输入选择可用专用 Skill

已有选定图片/截图且任务是忠实实现时，可使用当前可用的 `product-design:image-to-code`；已有指定 Figma 设计且要转代码时，可使用 `figma:figma-design-to-code`。先读取实际 Skill 定义及其必读路由，核对输入访问权限、依赖、输出格式与现有运行方式；未连接、无文件访问或无兼容导出能力时如实记录，继续能独立完成的本地工作，不宣称已调用。

调用前确认能保留正常任务、现有状态/权限、稳定定位和本地可打开的 HTML。若工具产出框架项目，先核对并实际验证其构建/导出路径、资源可携带性和离线打开要求，兼容后再纳入原型；不能只把框架入口改名为 HTML。依赖不兼容时保留已选设计依据，按本地 HTML 规范实现，不擅自改变交付载体。

仅在用户要求视觉探索且确有设计选择需求时展开相应探索；不因插件存在就触发多方案、Figma 写入或发布。方法本身不安装插件、连接 UIZZE、强制 Node 工具或自动发布站点。

## 3. 将任务和状态落实到页面

沿用现有 PAGE 及区域/控件/状态标识，明确任务/规则 → PAGE@版本 → 区域 → 控件/状态 → 实现定位。S2 已有业务对象/场景编号直接引用，不为套用 S4 结构强制提前建立全套 PAGE；S3 形成 PAGE 后继续沿用。S4 使用[页面结构规格](../../stages/prototype-design/references/page-structure-spec.md)，JSON、YAML 或清楚表格均可，自动检查派生数据注明主记录版本。

为本轮适用的加载/处理中、空数据、成功、失败、权限不足、部分完成等状态写明触发、用户看到的信息、允许操作与安全接续。取消/返回/重复等按任务覆盖；不适用说明业务理由，缺工具或未操作记未验证，不能写不适用。未知状态结果回来源阶段，不能用前端默认处理补业务规则。

先定义默认入口、并列核心路径、结果页/结果区域与返回，再安排单页细节。说明必要信息的位置和优先级，角色可见/可操作范围，长内容及小视口下的阅读和操作顺序。不能从现有 HTML 反推“所需范围已经完整”。

## 4. 实现并保持可操作

默认依[HTML 原型规范](../../stages/prototype-design/references/html-prototype-standard.md)生成自包含 HTML/CSS/JS 或该规范允许的本地资源包，无需后端。资源/字体来源和许可按实际材料处理；加载失败有可用回退。复用当前产品组件和已验证交互，样例、模拟算法及外部响应明确标识。

首屏是可供目标用户理解并开始任务的产品页面。重置、角色切换、故障注入和覆盖报告放在独立演示设置；准备初始条件后仍由正常入口完成任务。按钮要有事件、反馈、结果和可继续动作；不能用成功提示或跳到结果页冒充业务闭环。

可复用 CSS 变量和公共组件维持一致性，按设备和内容约束响应式布局；动效只在帮助理解反馈时使用，并按适用性支持减少动态效果。保留约定的定位标记及同版入口/样例说明。

## 5. 实际检查并保留证据

先读取当前浏览器/计算机工具及相应 Skill 的实际说明，再从正常入口点击、输入、返回，按事先定义的判据核对结果。关键任务包含允许与拒绝等适用路径；不能直接调用页面内部函数或改状态冒充用户操作。

按本期页面/视口/状态计划实际查看信息层级、长文本、遮挡、滚动、目标大小、标签、键盘/焦点和适用可访问性，检查任务产物的内容及后续用途。记录版本、环境/输入方式、数据、步骤、预期、实际观察、截图或其他可定位证据。截图可证明外观，源码/结构检查可证明声明；它们不能单独证明完成了任务。窄屏模拟不等于原生真机验证。

结构检查沿用阶段既有 Python 工具和[本地命令](../../references/local-tools.md)，不新增重复 schema 或把脚本通过写成体验通过。按需读取并使用当前可用的 `product-design:audit` 辅助定位 UX/可访问性问题；其截图先行和证据规则仍适用，结果回当前问题记录。

S4 按既定顺序完成 A03 独立品牌成品关卡、A04 任务操作及 A05 真人验证。一般 UX 审查不替代无开发上下文的品牌评审，专家、代理或自动化不作为真实目标用户。各阶段只报告实际执行范围，未检查项保留。

## 6. 增量修改与回填

先判断变化来自目标、规则、功能还是呈现，按来源更新上游或当前设计记录。读取实际旧版，列明受影响的 PAGE/区域、共享组件、状态及应保持的行为；保留旧快照和稳定标识，删除/拆合记录去向。无必要不重生成整页或重置风格。

修改后核对来源、标识和覆盖，实际复走受影响任务、共享使用处、邻接返回及异常路径。按证据判断旧视觉/用户结论的适用性，S4 沿用既定 no-go/conditions-go/go 分支，不另加审批或绕过必要真人补验。

在本阶段已有说明/质量记录中保存“采用的本地方法及版本、输入/产物位置、采用或未采用外部 Skill 的实际情况、检查及限制”。不新建成果编号、主事实来源或阶段状态。完成表示当前原型及实际检查有记录，不自动表示阶段生效、品牌符合或用户验证通过。
